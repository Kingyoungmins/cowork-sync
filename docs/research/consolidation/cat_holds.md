# holds — This subsystem decides which local bytes may leave this PC and which incoming bytes may land on it. It works at the granularity of whole change-sets, and it keeps every version it displaces in exactly one store (the hold registry). That registry is mirrored to the remote board, so no displaced version lives only on one disk. The subsystem owns: (a) the single hold registry, its record schema, its residence/state machine and its merge-file operator family; (b) the one revert detector; (c) the SNAPSHOT freeze, which merges the engine's git-epoch guard and the mass-change breaker into one mechanism; (d) change-set (CS) identity, publication timing, capture-at-trigger, whole-CS holds on the sender, closure applies on the receiver, and the CS view of save; (e) the guard contract that every other group (engine, data-handling, claude-integration, protocol, messaging-security) uses to put something on hold. Principles applied throughout: P1 (every displaced version goes to the board-mirrored registry), P2 (every hold and freeze is loud, to the human and to that seat's Claude), P3 (one registry, one operator family, one detector, one freeze; deleted mechanisms are listed in HS-00), P4 (unsupported cases are refused or deferred, as listed), P5 (all timers are local monotonic; ordering on the board is by board position) and P6 (every rule cites VERIFIED finding ids or the new sweep/holdcat experiments).

## v1 in scope
- One hold registry with four kinds (PATCH, PIN, SNAPSHOT, INCOMING) and a residence attribute (ON_DISK, OFF_DISK). Stored as an append-only local commit chain at refs/cowork-local/<b>/holds and mirrored to the board as protocol `hold` ops plus held/<id>/ blob entries.
- The merge-file operator family (REBASE, MASK, PARK, RESTORE) over stored-form blob pairs and triples. Git floor is 2.43.
- A two-tree loop (S_disk for apply, S_pub = MASK(S_disk) for publish) with a per-loop INV-MASK assertion.
- One bidirectional per-line revert detector fed by a local provenance journal. The journal is rebuildable from the live first-parent chain, which is never reset at save.
- SNAPSHOT freeze: git-epoch signals plus the unobserved mass-change threshold. Both directions freeze, there is one board event per episode, and release is by epoch return or a human command, never by timeout.
- A guard contract with PREDICATE guards (re-evaluated every loop, release automatically) and DECISION guards (released only by a named event or a human command). Guards compose with AND.
- Change-set identity keyed by seat_id, publication groups, publication at CS close or green checkpoint, capture-at-trigger with ready pairs rebased at every apply, and Cowork-CS commit trailers with per-CS path lists.
- B1 implemented as a whole-CS PIN hold, plus dependency bundling, deny-time shadow records and the U5 queue states (pending_leftover, offered, accepted, returned).
- A whole-path pre-image restore for a Claude-tool write whose hunks in that path all lie inside foreign-held symbols. It uses PARK and never splices.
- Receiver closure apply on the engine's per-path verifying writer, using two phases per closure, with apply coalescing.
- T0 checks on every outgoing tree and after every CAS re-merge, and T1 (the configured command) at checkpoints and at save.
- Durability rules for /cowork stop, uninstall, --purge, start in a fresh clone, and daemon restart.
- Commands: /cowork holds, /cowork hold show <id>, /cowork resolve <id> --publish|--discard|--park|--restore|--handoff, /cowork resume, /cowork done. MCP tool: cowork_checkpoint.

## v1 refuse/defer
- v2: interface breaks carried only through string literals or config keys (a JSON key renamed and read from .py and .cs). T0 drops string hits, so in v1 only a configured T1 command catches them. This is the residual part of c-interface-break-invisible-to-claims; status and the save report say 'no T1 configured' when T1 is absent.
- v2: per-symbol format-only classification and team-pinned formatter fingerprints (formatter-whole-file-rewrites, e-formatter-and-write-livelock). v1 relies on the HS-10 whitespace-equal exemption, the CS-04 claim PIN, the HS-11 breaker and claude-integration's advisory deny of repo-wide formatters.
- v2: a 'possible fork' detector for a new symbol that copies at least 80% of the tokens of a foreign-held symbol (handle_upload_v2, from deny-workarounds-by-agent). v1 relies on the deny/withhold texts, which say 'do not copy the function under a new name', and on the CS-04 dependency bundle.
- v2: T0 import-name resolution beyond Python `from <local module> import n` and JS/TS relative named imports (for example C# using/namespace moves and Python attribute access on `import x.y`). Those breaks are caught only by T1.
- Default off until the user signs off: automatic PARK of an ACTIVE record after 24 h (LCM-9). /cowork stop always parks.
- v1: refuse live mode in linked worktrees, including .claude/worktrees/* (engine rule). The WorktreeRemove 'not clean' marker spike for parked items is therefore not needed in v1.
- v1 fallback, not a refusal: a CS touching more than 256 paths carries no path list in its trailer. Receivers then defer at whole-commit granularity for that CS.
- v1: no cross-path atomicity guarantee for an apply closure interrupted by power loss in phase 2. Restart completes or rolls back the journaled closure before any snapshot is published (CS-12), and until then status shows 'apply incomplete'.
- Deleted, not deferred (HS-00): time-capped WIP publishes, NOTE-1 'incomplete' board records, per-hunk withdrawal, PostToolUse hunk restore, the contested set and TRANSFORM holds. The CS-12 receiver context line replaces NOTE-1 for the one split that remains (receiver deferral).

## interfaces
- EXPOSES ref refs/cowork-local/<b>/holds: an append-only commit chain in the common namespace. Each registry transition is one commit whose parent is the previous registry commit, written with `-c core.logAllRefUpdates=always update-ref --create-reflog <ref> <new> <old>` (CAS).
- EXPOSES record schema {id (ULID), owner peer_id, kind PATCH|PIN|SNAPSHOT|INCOMING, residence ON_DISK|OFF_DISK, state ACTIVE|CONFLICTED|PARKED|SUBSUMED|GONE|RESOLVED_PUBLISH|RESOLVED_DISCARD, offer none|pending_leftover|offered|accepted|returned, declines, displaced_by, paths[], H0/H1 stored-form blob oids (or stage1/2/3), guards[{name, class PREDICATE|DECISION, owner_group}], origin human|seat_id[/agent_id]|daemon, cs_ids[], peer_authors[], local_only bool, proto}.
- EXPOSES MASK(S_disk) -> S_pub to the engine loop (step 4), and the INV-MASK assertion result.
- EXPOSES defer-set additions to the engine apply (R6): INCOMING closures, SNAPSHOT freeze, and live Bash/PowerShell transactions.
- EXPOSES guard API to other groups: hold(paths, kind, guard, class, H0/H1|stages, origin, cs_id) -> record id. It attaches the guard to an existing record when H1 equals or rebases onto that record's H1 (HS-12).
- EXPOSES held-line-range cache per path (diff(S_pub, S_disk) in current disk line rows) to the PreToolUse gate. It is refreshed every loop and after each PostToolUse on that path.
- EXPOSES per-seat unacknowledged list (records created, withheld or restored this turn, keyed by agent_id) to the claude-integration Stop/digest renderer.
- EXPOSES board op `hold` {hold_id, rev, prev_rev, kind, residence, state, offer, guards, paths, origin, cs_ids, peer_authors} plus board tree entries held/<hold_id>/{h0,h1,s1,s2,s3} (blob ids only). protocol `request`/`request_status`/`answer` ops use req_id == hold_id.
- EXPOSES code-commit trailers: `Cowork-CS: <cs_id> state=closed|checkpoint seq=<n> author=<peer_id> checks=pass|fail|skipped paths=<n>` and `Cowork-CS-Paths: <cs_id> <base64url(zlib(sorted NUL-joined repo paths))>` when n <= 256.
- EXPOSES files: <gitdir>/cowork/prov/<b>.jsonl (provenance journal cache), <gitdir>/cowork/cs/<b>.json (open CS table and ready pairs, as a cache).
- CONSUMES from the engine: A[p] (per-path base), LA_C, S_disk, TIP = live_code(board tip), M_disk, the per-path verifying writer (CAS write, link-no-replace, .old ring), the list of verified-written paths per apply, the state-ref journal, the R3 base-move hook and the R10 adopt preconditions.
- CONSUMES from claude-integration: hook events with seat_id, session_id, agent_id and tool_use_id (PreToolUse, PostToolUse, PostToolUseFailure, PostToolBatch, PermissionDenied, Stop, StopFailure, SubagentStop, SessionEnd, UserPromptSubmit); Bash/PowerShell transaction open/close; fences and leases; seat liveness promoters.
- CONSUMES from protocol: the board fold (claim order by first-parent position), governor windows, offer answers (accept, decline, release, grant), and checkpoint heights for compaction.
- CONSUMES from data-handling: canon(newBlob, refBlob), the conflict-policy result per conflicted path (stages 1/2/3, TIP-on-disk), scope/portability verdicts, the EOL protocol-violation verdict and the churn ('generated?') verdict.
- CONSUMES from the region group: the symbol map on stored-form line rows (path, kind, qualname, line range), signature-change classification and identifier/import sets.
- CONSUMES from messaging-security: the secret tripwire verdict, filter-required failures, and the exec-surface quarantine set.

## rules
- **HS-00** The implementation MUST NOT contain any of the following mechanisms, and a CI grep/lint MUST fail the build if one appears. (1) Holding stores other than the HS-01 registry: refs/cowork-held/*, refs/worktree/cowork/*, .git/cowork/quarantine/*.patch, .git/cowork/conflicts/*, refs/cowork-local/<b>/conflicts/*, separate board conflict or handoff record types, or a write ring used as a store. (2) The 'contested set', or any rule in which claim state exempts, releases, narrows or re-keys a held change. (3) Per-hunk push-gate withdrawal, -U0 hunk subtraction, or symbol-range splicing of an outgoing blob, a working file or a saved tree. (4) PostToolUse/PostToolUseFailure restoring individual hunks. (5) TRANSFORM holds; EOL/BOM/mode handling belongs to data-handling's canon. (6) Time-capped WIP publishes (state=wip) and opt-in WIP materialisation. (7) Time-windowed 'recent provenance, do not fix' rules and NOTE-1 'incomplete' board records. (8) `git apply`, checkout, checkout-index or `read-tree -u` of a stored hold, park or snapshot tree. (9) Region-equals-history, reverse-patch-equality, revert-to-HEAD and symbol-hash revert detectors. Principles: P3, plus P6 for each VERIFIED failure cited.  _(covers: positional-patch-quarantine-misapplies, intra-file-withdrawal-mangles-file, hunk-withdrawal-publishes-signature-without-callers, claim-launders-held-revert, absorbed-hold-evades-history-detectors, provenance-rule-blind-to-withdrawal-deferral-save, posttooluse-restore-induces-workarounds, transform-holds-as-hunks)_
- **HS-01** Every reason why this PC's disk or outgoing tree differs from (team tip + its own ready, unblocked change-sets) MUST be a record in ONE registry. The registry is the commit chain at refs/cowork-local/<b>/holds, in the common ref namespace shared by all worktrees and never under refs/worktree/*. Each transition is a new commit whose first parent is the previous registry commit, and whose tree holds records/<id>.json plus the referenced blobs. Nothing is overwritten. The ref is updated only by CAS update-ref, with -c core.logAllRefUpdates=always and --create-reflog. The registry is re-attached on daemon start BEFORE the first snapshot is published. Principles: P1, P3.  _(covers: park-refs-in-worktree-namespace-vanish, local-only-holds-break-nothing-lost, no-history-undo)_
- **HS-02** A record's identity MUST be its id (a ULID). Its content MUST be the ORIGINAL stored-form blob pair (H0 = A[p] when the record was made, H1 = the held version), or stage1/2/3 for a conflict. Content hashes (path + H0/H1 oids) MAY be used only for dedup and display, never to decide what is masked, released or matched. Positional keys (line ranges, patch-ids, pre/post-image hashes) MUST NOT exist in the schema. One change MUST have one id: a guard that catches a change whose H1 equals, or REBASE-converges to, an existing record's H1 adds itself to that record's guard set instead of creating a new record. Principles: P3, P6.  _(covers: line-range-hold-misses-and-corrupts, hunk-identity-key-unstable, one-change-two-stores)_
- **HS-03** Blob content MUST enter the registry only through the pinned clean path: a private-index add, or `git -c attr.tree=<EPOCH_BASE> -c filter.<d>.required=true hash-object -w --path=<p>` for every discovered driver <d>. It MUST NOT come from `hash-object --stdin` without --path, from JS strings, or from raw tool_input. A record whose guards include filter-failure, secret-scan or unreadable, or whose path matches a U10 secret-like pattern, is LOCAL-ONLY. The board gets only the content-free stub {hold_id, owner, path, guard, state}; no blob oid and no held/ entry are ever published for it, and its bytes stay on the user's disk (never PARKed). The P1 exception is accepted because those bytes were never displaced. Principles: P1, P2.  _(covers: board-plaintext-and-permanence, splice-text-from-worktree-leaks-secret, local-only-holds-break-nothing-lost)_
- **HS-04** Every group MUST put things on hold only through the HS-01 registry, using a named guard with a fixed class. PREDICATE guards are re-evaluated at every loop and release automatically when the predicate turns false: claim (CS-04), dependency (CS-04/CS-06), t0 (CS-08), lock and unmaterializable (INCOMING), unreadable and unstable (HS-05). DECISION guards are released only by their named event or by a human /cowork resolve: revert (HS-10); conflict and claim-breach (data-handling); breaker and epoch (HS-11); join, restart and phantom (engine); eol-bom, eol-form, portability (human-created path), generated? and collision (data-handling); filter-failure and secret-scan (messaging-security, LOCAL-ONLY); host-reject (governor/HOST-CI); exec-surface, for local publishes and incoming changes in the quarantine set; review, for incoming 120000/160000 entries. A guard name the reading daemon does not know MUST be treated as a DECISION guard that this daemon never releases or transitions. Principles: P3, P2.  _(covers: single-guard-release-publishes-multiguard-hunk, version-skew-board-and-guards, held-bytes-mislead-local-claude)_
- **HS-05** Per-loop exclusions MUST NOT create records or board traffic while they last under 60 s on the local monotonic clock. They are: unreadable and unstable paths (S_pub[p] := A[p] for this loop); fenced or in-transaction paths on the snapshot side (not re-read; the previous snapshot blob is kept); and locked, fenced or in-transaction paths on the apply side (the closure is deferred). A condition that persists for 60 s or more MUST become exactly one record: a PIN with guard unreadable or unstable (LOCAL-ONLY stub) on the publish side, or an INCOMING record with guard lock on the receive side. The record releases automatically when the condition clears and produces one board op when created and one when released. Principles: P2, P3; INV-BUDGET.  _(covers: pending-path-base-misset-reverts, local-only-holds-break-nothing-lost)_
- **HS-06** Record lifecycle. Residence ON_DISK (the held bytes are on disk and masked) has the states ACTIVE and CONFLICTED. Residence OFF_DISK (the held bytes are only in the registry and the board; the disk has the team version) has the state PARKED. The terminal states are SUBSUMED, GONE, RESOLVED_PUBLISH and RESOLVED_DISCARD. After every apply step, ON_DISK records MUST be evaluated in this order: CONFLICTED (REBASE or MASK conflicts; the whole path is withheld, S_pub[p] := A[p]) > SUBSUMED (H1' == A[p]) > GONE (PATCH only: MASK(S_disk)[p] == S_disk[p]) > ACTIVE. OFF_DISK records MUST NOT be rebased per loop, masked or GONE-evaluated, and MUST NOT withhold a path; the one exception is that a record carrying claim-breach pins its path (S_pub[p] := A[p]) until resolved. When A[p] changes, an OFF_DISK record is checked once by single-step REBASE from its original pair: equal to A[p] means SUBSUMED, and a conflict leaves it PARKED. A record is born OFF_DISK whenever the daemon itself displaces the bytes. That covers the data-handling conflict policy (once the TIP write of p is verified; while a lease defers that write, the record is ON_DISK CONFLICTED), claim-breach, deny-time shadows (CS-06), pure-breach restores (CS-05), PARK by stop, resolve or timer, and SNAPSHOT --restore. Offer status is a separate field: pending_leftover -> offered (at any claude-integration promoter) -> accepted (the holder's daemon writes the published live commit oid into the record, and the requester's next check marks it SUBSUMED) | returned (after a decline or release; residence unchanged; after 2 declines of the same (requester, key, H1) it goes to the requester's human). Principles: P1, P2, P3, P6 (sweep/holdcat X2 VERIFIED: a conflict-policy record evaluated with the on-disk order rebases with rc=1, so it would be CONFLICTED and withhold its path forever; same-line and adjacent-line cases).  _(covers: stale-hold-resurrects-team-revert, absorbed-hold-evades-history-detectors, conflict-tree-applied-or-auto-resolved, permanent-hold-never-converges, one-change-two-stores)_
- **HS-07** All record arithmetic MUST use `git merge-file -p --object-id` (git >= 2.43; /cowork start refuses older git and there is no file-based fallback), with A = the engine's per-path base A[p], never tree(LA_C)[p]. REBASE: H1' = merge-file(cur=A[p], base=H0, other=H1), always single-step from the ORIGINAL pair, with H0' = A[p]. MASK: for a PATCH, merge-file(cur=S_disk[p], base=H1', other=H0'); for a PIN, the A[p] entry (or absent); a SNAPSHOT freezes; an INCOMING record defers. PARK writes the MASK result to disk through the verifying writer (CAS expected = S_disk[p]). RESTORE is merge-file(cur=disk, base=H0, other=H1); a conflict opens a 3-way resolve session showing provenance, never a fuzzy apply or a checkout. For revert taint, H1 MUST be taint-only (A[p] plus only the tainted -U0 hunks), so that untainted edits in the same save publish. Principles: P3, P6 (exp_j_fuzz rebased mask 160/160, static mask wrong in 19/19; exp_r_rebase single-step equals iterative in 347/347; exp_f git apply lands the change in the wrong function).  _(covers: line-range-hold-misses-and-corrupts, hunk-identity-key-unstable, stale-hold-resurrects-team-revert, positional-patch-quarantine-misapplies)_
- **HS-08** Each loop MUST keep two trees. S_disk (the engine's private-index snapshot) is the ONLY tree used as an apply input (M_disk = merge-tree --merge-base=A S_disk TIP). S_pub = MASK(S_disk, ON_DISK records, PIN and pending groups) is used ONLY for the outgoing merge and the push. Nothing locally merged or written is ever recorded as applied; A changes only per the engine's verified-write and confirmed-push rules. INV-MASK is asserted after every MASK: re-applying every ON_DISK record to S_pub must reproduce S_disk, and diff(A, S_pub) must contain no line tainted by any ON_DISK revert record. On failure: no push this loop, a doctor error, a loud notice to the human and to every live seat's Claude, and never a fallback to pushing S_disk. N=3 consecutive apply failures for the same reason MUST publish a board health state ('<peer> not receiving <path>: <reason>'). Principles: P2, P6 (masked-tree-as-apply-base-starves VERIFIED d1).  _(covers: masked-tree-as-apply-base-starves, absorbed-hold-evades-history-detectors, hunk-identity-key-unstable)_
- **HS-09** Claim state MUST NOT be an input to detection, MASK, REBASE or release. The PreToolUse(Edit|MultiEdit|Write|NotebookEdit) gate MUST deny (G1, exit 2) any edit whose target line range overlaps, within ±1 line, a held region of an ON_DISK PATCH record. The held region is read from the per-path cache of diff(S_pub, S_disk), which is refreshed every loop and after every PostToolUse on that path. The deny names the record id, its origin and peer author, and '/cowork hold show <id>'. A stale cache is safe: a Claude edit that lands inside a held region makes the MASK conflict, so the record becomes CONFLICTED and nothing from that path is published. PIN paths are not denied. Instead, the seat's next hook output carries one additionalContext line per (seat, path, turn) saying that the path is pinned in record <id> and why. PostToolUse(Read) and SessionStart MUST list the ON_DISK records in files the seat reads, within the 600-char attribution cap. When a record is created from this seat's own change, the seat's next hook output MUST say that the change is not shared. Principles: P2, P6 (exp_a claim_exempts reverts B's fix; d2 shows an adjacent edit cannot be separated, CONFLICT rc=1).  _(covers: claim-launders-held-revert, held-bytes-mislead-local-claude)_
- **HS-10** Exactly ONE revert detector MUST run on every new S_disk BEFORE that loop's merge. Its input is the provenance journal. For every live commit that LA_C advances over on the first-parent chain, the journal records, per path: the author peer_id (base-move commits are attributed to 'branch:<X>'), the cs_ids, and the SHA-1 of every non-trivial added and removed line (not blank, not punctuation-only after strip). It is appended when LA_C advances, kept 14 days, and rebuilt from the live first-parent chain if missing; the chain is never reset at save (engine INV-FF). A -U0 hunk of diff(A, S_disk) is UNOBSERVED unless it was produced inside an Edit/Write/MultiEdit/NotebookEdit hook window of a live seat. Bash/PowerShell writes, human saves, /rewind, git verbs and external tools are unobserved. An unobserved hunk is TAINTED if it (a) removes a line whose hash the journal lists as added by another peer, or (b) adds a line whose hash the journal lists as removed by another peer, within the window. A removed/added line pair that is identical after whitespace normalisation is exempt (format-only; claims still gate it). Each tainted hunk MUST become a PATCH record with guard revert and a taint-only H1. It is created before any merge in that loop, never auto-published and never offered to a queue, and leaves only by SUBSUMED or a human /cowork resolve. Principles: P2, P3, P6 (sweep/holdcat X3 VERIFIED: the delete/modify-only rule let a stale buffer re-add a peer-deleted line and publish it; exp_more h: blame after a squash save loses provenance).  _(covers: stale-editor-buffer-reverts-peer-work, rewind-restore-code-reverts-teammates, b-bypass-revert-of-unsaved-peer-work, save-squash-erases-provenance, absorbed-hold-evades-history-detectors, user-git-ops-broadcast-as-revert, worktree-reset-commands-broadcast-revert, local-git-ops-propagate-as-reverts, bash-git-verbs-revert-and-markers, human-claim-breach-and-claude-tramples-human, formatter-whole-file-rewrites, e-formatter-and-write-livelock)_
- **HS-11** The engine's git-epoch guard and the mass-change breaker MUST be ONE mechanism: a SNAPSHOT record, one per episode. Triggers (any one): an unexpected change to symbolic HEAD, the HEAD oid, refs/stash or ORIG_HEAD, or growth of logs/HEAD, other than the daemon's own pre-registered adopt; any engine R8 marker (MERGE_HEAD, CHERRY_PICK_HEAD, REVERT_HEAD, AUTO_MERGE, BISECT_LOG/BISECT_START, rebase-merge/, rebase-apply/, sequencer/); unmerged entries in the user index (read with GIT_OPTIONAL_LOCKS=0); index.lock present for more than 30 s (the loop already pauses up to 10 s per engine rule); or one snapshot whose UNOBSERVED delta touches more than max(10 files, 2% of tracked files) or deletes a file that has peer-provenance lines. Effect: fetch continues, but there is NO apply and NO publish for this branch's worktree. One board event is posted ('<peer> paused: <reason>'), and the human (status line plus an OS notification) and every live seat's Claude (next hook additionalContext) are told. Release: (1) automatically, when the epoch equals expected (HEAD on refs/heads/<b> at H_adopt, stash oid as recorded, no markers) AND the unobserved delta is at or below the threshold; the whole batch then passes HS-10 before anything publishes; (2) /cowork resume, which is refused unless symbolic HEAD == refs/heads/<b> and runs engine R9; (3) /cowork resolve <id> --restore, which writes the team version through the verifying writer, with every displaced path becoming an OFF_DISK PATCH record (displaced_by=snapshot-restore); (4) --publish, which re-runs HS-10 over the batch, turns tainted hunks into revert records, publishes the rest, and lists that residue in the prompt. A timeout MUST NEVER release it. Principles: P2, P3, P4, P6 (exp_k_stash: with apply continuing, stash pop exits 1; e17/e10/e13: stash, restore and checkout -- leave no marker).  _(covers: user-git-ops-broadcast-as-revert, git-ops-publish-team-revert, branch-switch-publishes-other-branch, worktree-reset-commands-broadcast-revert, local-git-ops-propagate-as-reverts, human-git-mass-revert, breaker-freezes-publish-not-apply, in-progress-ops-not-paused-conflict-markers-broadcast, bash-git-verbs-revert-and-markers, formatter-whole-file-rewrites, single-guard-release-publishes-multiguard-hunk)_
- **HS-12** Guards MUST compose with AND: each (record id, guard) pair is released separately, and a line is published only when every guard covering it is released. `/cowork resolve <id> --restore` releases only the guard that caused the displacement (conflict, claim-breach or park); every other guard stays. Every resolution output (--restore, --publish, a 3-way resolve, a returned handoff) MUST pass HS-10 taint and the claim gate again as a new local change. The single exception is data-handling's claim-breach restore: the holder's own version inside the symbol it holds is recorded RESOLVED_PUBLISH and is not taint-flagged. Every resolution MUST be a fold-level CAS on the record's rev (HS-14). Resolving a record that the board fold shows as ACCEPTED, SUBSUMED, GONE or RESOLVED_* MUST be a no-op with a message. Principles: P2, P3, P6 (x1: the conflict stage-2 oid equals the hold's H1; exp_more i: two `def helper` after a duplicate resolve).  _(covers: single-guard-release-publishes-multiguard-hunk, one-change-two-stores)_
- **HS-13** A record is DURABLE only when its `hold` op, with its held/<id>/ blobs, is on the remote board's first-parent chain. LOCAL-ONLY records are never durable. /cowork stop, /cowork uninstall and uninstall --purge MUST wait up to one governor window for the outbox push and then REFUSE, listing ids, while any non-terminal record is not durable or any LOCAL-ONLY record exists. The overrides are --discard-holds=<ids> (each logged as a RESOLVED_DISCARD board event) or --export <dir> (git bundle of the registry ref and blobs). After that, /cowork stop MUST PARK every ACTIVE record through the verifying writer (team version on disk; displaced_by=stop) and list them. A daemon exiting because it has no lease MUST NOT park. /cowork start MUST re-attach the local registry, import the user's own non-terminal records from the board fold (fresh clone, or after a purge), and offer RESTORE before the first publish. SessionEnd prints this worktree's ON_DISK and OFF_DISK counts. Principles: P1, P2.  _(covers: local-only-holds-break-nothing-lost, park-refs-in-worktree-namespace-vanish, no-history-undo, orphan-daemon-uninstall, uninstall-deletes-state-daemon-orphaned, held-hunk-escapes-via-branch-commit)_

## invariants
- **INV-NOLOSS-H** Every byte change written by a human or a Claude is, at every later moment, in exactly one of: live_code(board tip) or the saved branch; a non-LOCAL-ONLY record (ON_DISK or OFF_DISK) reachable from the remote board within one governed push; a LOCAL-ONLY record whose bytes are on the user's disk; or a RESOLVED_DISCARD event produced by a human command.

## open questions
- CONTRADICTION between binding resolutions, reconciled here and needing confirmation from claude-integration. claude-integration's Bash rule says 'restore the holder's current version for exactly those hunks' and 'B1: a hunk in a foreign-claimed symbol is never pushed'. LCM-5/LCM-12 say 'deny/restore of Bash diffs is not used; nothing is ever subtracted from a file; PostToolUse never rewrites the author's disk'. Chosen: B1's invariant is met by the whole-CS PIN (CS-04), because a held hunk is never pushed. The disk restore happens only for PURE-BREACH paths, as a whole-path PARK to the pre-image under CAS (CS-05). Mixed paths keep their disk bytes. No hunk splice is ever used, because of the VERIFIED intra-file-withdrawal-mangles-file result.
- CONTRADICTION with the engine lint. LCM-3/LCM-16 rely on `add -A`, `read-tree -m -u` and checkout-index rollback, which the engine forbids. Here they are re-expressed as the engine's explicit snapshot list and a two-phase closure on the per-path verifying writer (CS-12). The engine group must confirm three points: the closure journal in the state ref; the longer ENOENT window, which now spans a whole closure; and restart completion or rollback.
- Correction to LCM-11 (own group), from sweep/holdcat X1 VERIFIED. 'Capture at trigger' publishes a revert of an intervening apply unless the ready content is stored as an (A_cap, R) pair and rebased at every apply (CS-03). Engine asserts (b) and (c) pass on the bad tree, and HS-10 exempts observed edits, so nothing else catches it.
- Correction to LCM-1/LCM-2 (own group), from sweep/holdcat X2 VERIFIED. Data-handling's conflict record (TIP on disk, LOCAL held), evaluated with LCM-2's per-loop order, rebases with rc=1 and would sit in CONFLICTED forever, withholding its path. Fixed by adding residence ON_DISK/OFF_DISK (HS-06): daemon-displaced records are born PARKED and never mask or withhold. The 'later edits are withheld' consequence is REASONED from the state-machine semantics, not separately measured.
