# claude — Connect each Claude Code session to the per-user-per-repo cowork-sync daemon so that (a) Claude learns about claims, conflicts, holds and teammates' changes at the moment it acts, in fixed factual wording, inside a hard per-seat token budget; (b) the daemon gets accurate attribution of every Claude write (which seat, which tool_use, which change-set) and the timing signals it needs (apply-deferral leases, Bash transactions, turn boundaries); and (c) refused or withheld work is recorded at the moment it happens. Hooks are advisory: correctness lives only in the daemon's publish gate (B1) and verifying writer (B2), so every hook failure mode degrades to a loud pause or to extra holds, never to a silent bypass.

## v1 in scope
- User-scope plugin from a GitHub marketplace (sha-pinned): exec-form node command hooks only, one dependency-free loader, one per-session stdio MCP server, one slash command /cowork with human-only verbs, esbuild single-file bundles for Node >= 20.
- PreToolUse gate for Edit|Write|MultiEdit|NotebookEdit with outcomes G1-G4 (deny / silent pass / offline pass / daemon-down pause); never 'allow'; 'ask' only for a human override token.
- One apply-deferral lease table: INFLIGHT (per tool_use_id), READ (per full Read) and Bash/PowerShell TXN (per worktree), all on the daemon's monotonic clock.
- Claim prediction at PreToolUse on a normalized view; authoritative changed-symbol set from the PostToolUse pre/post diff; post-hoc foreign-symbol hits become a request plus a whole change-set PIN hold (no disk rewrite).
- Bash/PowerShell/Monitor tool-window attribution and an advisory deny list (git verbs that move HEAD/index/worktree, repo-wide formatters, in-place writers into foreign-claimed files, cowork CLI human verbs, worktree creation).
- Seat identity per claude process; /clear, /compact, in-process /resume and /fork keep the seat; multiple sessions per person are separate seats under one daemon.
- Context injection: SessionStart/SubagentStart standing rules + digest, UserPromptSubmit digest delta, PostToolUse attribution and hold notes, deny and held-change reasons, one Stop block per turn; ko (default) and en templates.
- Delivery: per-seat hook pull cursor as the carrier of record; inbox doorbell only through the session's own MCP child, only to idle seats, only for action-required events, inside wake caps.
- Per-seat cost budget with pull-mode fallback, apply coalescing into a busy seat's read files, and an interactive soak acceptance test.
- Daemon lifetime by leases from hooks/MCP, newest-version-wins handshake, env allowlist at spawn, uninstall/disable detection; loud human surfaces (systemMessage, OS notification, status.json).
- Turn and checkpoint signals for change-set (CS) boundaries consumed by the local-change-mgmt group.

## v1 refuse/defer
- v1: refuse - worktree-isolated subagents (Agent isolation:'worktree'), EnterWorktree, `claude -w` sessions and linked worktrees are not coordinated: the edit-class gate in them is a pass-through with a one-line note, EnterWorktree and explicit isolation are denied, `git merge` back is advisory-denied. v2: an import tool that replays a worktree diff as gated Edits.
- v1: refuse - a Claude Code session without `node` on its PATH has no seat (its hooks cannot run); /cowork start and doctor refuse there with the exact fix; its writes are human-class and stay covered by B1 and the LCM-5 revert detector. v2: optional bun-compiled fallback binary.
- v1: refuse - a session where hooks are disabled by policy (disableAllHooks, allowManagedHooksOnly) while our MCP server runs (state NO-HOOKS) pauses the whole checkout (fetch only) with a loud notice; per-seat handling is v2.
- v1: refuse - project-scope installation of the plugin, Claude Code older than 2.1.270, Node older than 20, two live checkouts of the same repo and branch by one OS user.
- Not used in v1 (by design, P3): mcp_tool hooks, http hooks, prompt/agent hooks, channels (research preview), plugin monitors (experimental), WorktreeCreate hooks (would replace git's default in every repo), bashEditDiff as an enforcement input, PermissionRequest-based lease extension.
- v2: an opt-in chaining statusLine script (a plugin cannot set statusLine; v1 relies on systemMessage at the next hook, OS notifications and status.json).
- Not handled, documented: Write of a file that cannot be fully read (the 1.3 MB hub.py) is refused by the host; Edit is the only path and doctor says so. Obfuscated shell writers are not parsed; B1 and LCM-5 are the backstop.
- Off by default (needs user sign-off, see CCI-20): Claude editing code in a turn started by a teammate doorbell.
- Owned elsewhere - rewind-restore-code-reverts-teammates: Claude Code fires no hook for /rewind 'Restore code', so this subsystem cannot see it; the LCM-5 per-line taint detector classifies the write as UNOBSERVED and holds the revert.
- Owned elsewhere - user-git-ops-broadcast-as-revert, git-ops-publish-team-revert, local-git-ops-propagate-as-reverts, human-git-mass-revert, b-bypass-revert-of-unsaved-peer-work, branch-switch-publishes-other-branch, in-progress-ops-not-paused-conflict-markers-broadcast: engine epoch guard (loop step 0) and LCM-5/LCM-6; this subsystem only contributes the advisory Bash/PowerShell deny for Claude-issued git verbs (CCI-14), which is not load-bearing.

Only the MCP server holds CLAUDE_CODE_MESSAGING_TOKEN; it posts {"type":"auth","token":...} and then the message to its own session's socket.

- Consumed from other subsystems: claim/region cache and board fold (protocol, region detection), hold registry ACTIVE records and MASK (LCM-1/2/4), CS manager (LCM-10/11/12/13), applier defer set D (engine R6), publish gate B1 and verifying writer B2, apply journal (LCM-5), templates T1-T5 (messaging-security), quarantine set (EXEC-SURFACE), offline/auth health (RULE AUTH), pinned clean path for blobs (BOARD-CONTENT 3).
- Produced for other subsystems: lease table (path -> deferred), TXN state per worktree, attribution of each write (seat_id, tool_use_id, agent_id | human), confirmed claims tagged change_set=(seat_id, tool_use_id), CS boundary events (open, close, checkpoint, capture-at-trigger), deny-time request records, seat states (FULL, HOOK-ONLY, NO-MCP, NO-HOOKS, DEGRADED, PAUSED, PULL-MODE) for the board HEALTH record.

## rules
- **CCI-01** HARD BOUNDARY STATEMENT (spec text, verbatim): cowork-sync has exactly two hard boundaries, both inside the daemon: (B1) the PUBLISH GATE - before any push to the live code ref, every changed hunk is mapped to symbols, and a hunk in a symbol covered by a foreign claim earlier in board publication order is never pushed; and (B2) the VERIFYING WRITER - the daemon writes a working-tree path only if its current bytes equal the expected pre-image, skipping leased paths. Every Claude Code hook in this subsystem is ADVISORY: it gives early denies, feedback and attribution, and MUST NOT be relied on for correctness. Implementers MUST keep: no hook ever publishes; a hook failure can only cause a pause, a hold or a lost note; every claim-safety test asserts on the remote ref with `git cat-file`, never on whether the local Edit happened. [P2, P3, P6: VERIFIED run1 shows ENOENT, exit 1, timeout and mcp_tool isError all let the Write through.]  _(covers: gate-fails-open-on-every-hook-failure, mcp-gate-fails-open, fail-open-enforcement, deny-then-bash-workaround, bash-powershell-bypass-after-deny)_

- **CCI-04** GATE OUTCOMES (PreToolUse Edit|Write|MultiEdit|NotebookEdit; Bash|PowerShell|Monitor and Agent|EnterWorktree use the same G1-G4 for their advisory denies) - exactly four outcomes. G1: the daemon answered with a refusal -> exit 2 with a stderr reason from a fixed template (CCI-21). G2: the daemon answered with no refusal -> exit 0 with empty stdout or JSON containing only hookSpecificOutput.additionalContext (plus systemMessage for the human); the gate NEVER emits permissionDecision 'allow' and never 'ask' (single exception: CCI-25 override). G3: the daemon answered but the remote is unreachable or auth expired -> decide from the claim cache of the last successful fetch as G1/G2; new claims stay TENTATIVE until reconnect (RULE AUTH 5); the OFFLINE text goes out once per offline episode (systemMessage + additionalContext), once more at 10 min offline, and in every digest; no 'ask'. G4: the daemon is unreachable -> the loader spawns it detached and retries until its internal deadline, then exit 2 with the G4 text; internal exceptions also map to the G4 text with cause 'hook error'. /cowork pause (human only) is the escape, and the paused state is published on the board as 'not coordinated'. The MCP server never returns isError for status tools. NEEDS USER SIGN-OFF (carried from the binding resolution; G4 pause stays the default): 공유 동기화 프로그램이 이 PC에서 멈춰 있을 때, Claude의 코드 수정도 멈추고 알려줄까요(기본안), 아니면 알림만 띄우고 계속 수정하게 한 뒤 나중에 공유하기 전에 검사할까요? [P2, P3, P5]  _(covers: gate-returns-allow-skips-prompts, offline-auth-claims, fail-open-enforcement)_
- **CCI-05** GATE DEADLINES AND IN-MEMORY ANSWERS: every hook declares timeout 10 (SessionEnd: 2). Loader internal deadline from process start: 1.5 s for gating and all other events, 3 s for SessionStart; on expiry gating events take G4 and others exit 0, so the host timeout (which fails open, VERIFIED run1) never fires first. The daemon answers gate requests only from memory: claim and region cache, board fold, and trees parsed in a worker_threads pool cached by blob oid (LRU, 300 MB cap). It never waits on git, the network or a parse; if the current file's tree is not ready it uses the conservative fallback region (enclosing indentation block or top-level def by regex scan), and the PostToolUse diff stays authoritative. If the verifying writer is mid-write on the same path, the reply waits for that one single-path write, at most 250 ms. SUSPECT own claim (protocol 10b(4)): within 100 ms the daemon replies with an `extend` frame that raises this request's loader deadline to at most 7.0 s from process start (>= 3 s margin under the 10 s host timeout), runs one fetch, then answers G2 if the board still shows the claim valid, else G1 with 'cowork-sync cannot confirm this session still holds {sym}: offline for {dur}'; only SUSPECT may extend, at most once per request. Budgets: daemon-side handling <= 15 ms p95; end-to-end <= 60 ms p95 on Windows; non-live fast path <= 45 ms p95 with zero IPC; the main event loop is never blocked > 20 ms (monitorEventLoopDelay; exceeding it is shown in status). [P2, P5, P6: VERIFIED e12 main-thread parse blocks 337-368 ms; VERIFIED e11 p50 30.8 / p95 42.8 ms.]  _(covers: hook-latency-stall-fail-open-or-hang, gate-latency-default-600s, hook-latency-event-loop-stall, sleep-offline-stale-and-suspect-claims)_
- **CCI-06** SEAT IDENTITY AND SEAT END: a SEAT is one claude process. seat_key = SHA-256(CLAUDE_CODE_MESSAGING_SOCKET) when that env is present, else the claude pid (process.ppid of exec-form hooks and of the MCP server; VERIFIED equal). seat_id = random 128-bit minted by the MCP server at process start and sent in hello; the daemon mints it only for a seat whose MCP server never registers. Claims, leases, transactions, read sets, budgets, cursors and request queues are keyed by seat_id; session_id is an attribute only. /clear, /compact, in-process /fork|/branch and in-process /resume keep the seat, and SessionStart re-injects the digest (CCI-17). SessionEnd is NOT a seat end (it fires with reason 'clear' inside a live process). SEAT END = MCP stdin EOF (the MCP server sends seat_end and exits within 1 s) OR the claude pid no longer exists (the daemon checks every 5 s with process.kill(pid, 0)). A resume or fork in a NEW process is a new seat; it adopts a dead seat's claims only if the old pid is gone and the old seat's last transcript_path equals the new SessionStart's transcript_path within 5 min on the daemon's monotonic clock; otherwise the protocol orphan rules apply. MCP IPC loss without seat_end while the pid lives and hooks keep arriving: the seat stays guarded (hooks gate), its delivery state becomes HOOK-ONLY, and one notice says 'cowork-sync: live notices for this session are off ({cause}); /mcp can reconnect the cowork server' - this replaces protocol 11(c)'s UNGUARDED for that case. Several sessions of one person are several seats; texts say 'your other session ({label})' with label = 'session N' numbered per daemon. A session touching a second live repo registers lazily with that repo's daemon (HOOK-ONLY there). A second live checkout of the same repo and branch by the same OS user is refused at /cowork start, naming the first. [P3, P5]  _(covers: seat-identity-vs-session-id, clear-compact-resume-orphan-claims, mcp-or-daemon-death-fails-open-and-stuck-fences, clones-worktrees-identity)_
- **CCI-07** SEAT HEALTH STATES, SPLIT BY CAUSE: DEGRADED (transient host failure) is entered when the daemon observes a PostToolUse or PostToolUseFailure for an edit-class tool_use_id with no matching gate request, or 60 s without hook traffic from a seat whose pid lives, whose MCP heartbeat continues and which is mid-turn (UserPromptSubmit seen, no Stop since). Effect: only that seat's read set and edit set of the last 30 min are deferred for applies (incoming kept pending in memory), publishing continues through B1, and the DEGRADED text goes out on the seat's next working hook; recovery after 3 consecutive matched Pre/Post pairs; never a whole-repo stop. NO-HOOKS (structural policy): ANY hook from a seat_key (SessionStart, the UserPromptExpansion of /cowork start, PreToolUse, PostToolUse, ...) counts as proof that hooks run, so a session opened before /cowork start is never misread; NO-HOOKS is inferred only when the seat calls a cowork MCP tool and no hook from its seat_key arrives within 10 s afterwards (PostToolUse '.*' fires for every tool call, so a working hook layer always reports inside that window), or from a static hit of disableAllHooks / allowManagedHooksOnly in managed settings (C:\Program Files\ClaudeCode\, /Library/Application Support/ClaudeCode/, /etc/claude-code/, including managed-settings.d), user, project or local settings -> v1: the checkout pauses applies and publishes (fetch continues), with a systemMessage through any channel, the state in status.json and an OS notification naming the setting (RULE POLICY-DETECT 3). NO-MCP (hooks without MCP): gating and attribution work, delivery is HOOK-ONLY. A session in which neither our hooks nor our MCP server run is invisible: its writes are human-class (B1 and LCM-5 still hold), and the static check at /cowork start reports the cause. Each seat's state is published in its board HEALTH record. [P2, P4]  _(covers: policy-fail-open, mcp-or-daemon-death-fails-open-and-stuck-fences, gate-fails-open-on-every-hook-failure)_
- **CCI-08** ONE APPLY-DEFERRAL LEASE TABLE (merges the claude-integration fence, the data-handling INFLIGHT/READ_FOR_WRITE leases and the Read lease). INFLIGHT: acquired at PreToolUse(Edit|Write|MultiEdit|NotebookEdit) only after G2, keyed by tool_use_id, refcount per path; the pre-image bytes are captured in daemon memory (64 MB total cap; beyond it the private-index blob oid is used). Released by: PostToolUse or PostToolUseFailure with that id; PostToolBatch for every listed id; the seat's UserPromptSubmit, Stop, StopFailure, SessionEnd or seat end (all of that seat's leases); SubagentStop (leases whose PreToolUse carried that agent_id); backstop 120 s. NOT released by the seat's next PreToolUse (parallel siblings would release each other). READ: acquired at PostToolUse(Read) of a FULL read by that seat; released by that seat's next Edit/Write PostToolUse on the path or after 120 s; renewed on that seat's hook activity at most 3 times, hard cap 300 s from first acquisition. Ranged reads create no lease and are recorded with their ranges. TXN: see CCI-11. The applier skips every leased path; the incoming change stays pending and later 3-way merges with whatever Claude wrote. EXPIRY GUARD: if an INFLIGHT lease expires before its Post event and the verifying writer wrote that path after the lease was acquired, the hunks of that tool_use on that path lose the LCM-5 'observed Edit/Write' exemption and are taint-checked as UNOBSERVED (this closes a Write, approved after a long permission prompt, overwriting an apply and publishing an unflagged revert). Expired leases are listed in status; more than 5 expiries per seat-hour flags doctor. All times are on the daemon's monotonic clock. Binding conflict resolved: 120 s (data-handling: VERIFIED Write staleness check runs before hooks, DOCUMENTED PreToolUse runs before the permission prompt) over 20 s (claude-integration), with the claude-integration release list. [P1, P2, P3, P5]  _(covers: fence-and-claim-leak-without-post-event, fence-vs-inflight-apply-and-stuck-fence, write-staleness-check-precedes-hooks, e-formatter-and-write-livelock, subagent-identity-fence-and-handoff-timing)_
- **CCI-09** CLAIM PREDICTION VS CONFIRMATION: PreToolUse locates the edit on a NORMALIZED view (BOM stripped, CRLF->LF, U+2018/2019/201C/201D folded to ASCII quotes) and maps matches back to raw offsets; replace_all lists every match; Write maps the whole new content against the pre-image; NotebookEdit maps by cell id. The prediction is used ONLY for G1/G2 and to record TENTATIVE local claims; it is never published. At PostToolUse the daemon diffs the captured pre-image against the post-image on the normalized view with EOL-only and BOM-only hunks dropped; only that authoritative changed-symbol set becomes CONFIRMED claims eligible for publication, and every hunk is tagged change_set=(seat_id, tool_use_id). Tentative claims not confirmed are discarded when the INFLIGHT lease is released. If locating fails entirely the edit is never turned into a whole-file claim: the gate answers G2 and the PostToolUse diff decides. ## invariants
- **INV-CI-B1** In every hook failure mode (node missing, bundle load error, thrown exception, hook timeout, MCP server killed, daemon killed or hung, /cowork pause) and for every write form (Edit, Write, NotebookEdit, Bash python -c, PowerShell Set-Content, formatter), no hunk inside a symbol claimed earlier in board order by a foreign seat ever appears in a pushed live code commit.
  TEST: Fault-injection matrix (7 failure modes x 6 write forms) on a file:// remote with a fake peer holding foo(): after each run `git cat-file -p` of the live code tip shows foo() byte-identical to the holder's version, and a request record for the attempt exists on the board.
- **INV-CI-NOALLOW** No hook output ever contains permissionDecision 'allow'; 'ask' is emitted only when a valid human override token exists for that seat and symbol.
  TEST: CI grep of the bundle plus a runtime assertion in the output encoder; Agent SDK test in default mode with no allow rules shows the permission prompt still appearing for a non-conflicting Edit; dontAsk mode still auto-denies.
- **INV-CI-LEASE** On the daemon's monotonic clock no INFLIGHT lease outlives 120 s, no READ lease 300 s and no TXN 120 s, and every lease is released by its Post event, batch, seat sweep event or expiry.
  TEST: Property harness that randomly drops Post events (deny by a second plugin hook, permission 'No', Esc, plan mode, StopFailure) and asserts lease ages, plus that an incoming change to the path lands within 125 s.
- **INV-CI-EXPIRY-TAINT** An Edit/Write whose INFLIGHT lease expired before its Post event, on a path the verifying writer wrote after the lease was acquired, never publishes a hunk removing a teammate's line without passing the LCM-5 taint check.
  TEST: Scripted session: Read f, PreToolUse(Write), hold the permission prompt 150 s while a peer change is applied to f, approve; assert the teammate's line is still in the live tip and an LCM-5 PATCH record exists.
- **INV-CI-RECORD-FIRST** Every G1 for a foreign claim and every post-hoc foreign-symbol hit has a durable local record (fsynced tmp bytes or a stored blob) before the hook replies, and that record reaches the board with the next push.
  TEST: kill -9 the daemon immediately after the G1 reply in 100 trials; after restart the request exists in every trial and appears on the board after one push.
- **INV-CI-CAP** Every injected text respects its cap, and in SessionStart output every conflict and held-change line lies within the first 1,500 chars.
  TEST: Fuzz digests with 200 claims, 50 requests, 64-char names and 200-char symbol keys in ko and en; assert lengths and line positions.
- **INV-CI-WAKE** Per conflict at most one doorbell reaches the causer and at most one the holder, bystanders receive none, no doorbell is caused by a wake-originated turn, and the per-seat (1 per 10 min, 4 per hour) and team (12 per hour) caps hold.
  TEST: 4-seat stub inbox (implements the auth line, counts deliveries), 30-minute storm of 6 conflicts plus scripted polite replies with all seats idle; assert counts and that each event still appears in the target's next hook output.
- **INV-CI-ASK-ONCE** Each request id appears in at most one Stop block, ever, and no request is lost when Stop does not fire.
  TEST: Holder runs 10 turns with the request pending: exactly 1 Stop block names it; Esc, StopFailure and a dead MCP server at turn end never lose the request (it is in the holder's queue within 10 min).
- **INV-CI-TOKEN** The bytes of CLAUDE_CODE_MESSAGING_TOKEN never appear in the daemon's environment, IPC frames, logs, board records or files on disk.
  TEST: Run with a canary token value; grep the daemon env (process listing), captured IPC, <gitdir>/cowork/**, CLAUDE_PLUGIN_DATA/** and pushed objects: zero hits.
- **INV-CI-NO-ORPHAN** The daemon makes no push and no working-tree write more than 2 min after its last valid lease and exits within 10 min; a plugin disable or a deleted ipc.key stops it within 30 s.
  TEST: Kill every MCP server and stop issuing hooks: tasklist/ps and the remote show no push after 2 min and no process after 10 min; /plugin disable and deleting the key each stop it within 30 s.
- **INV-CI-SEAT** /clear, /compact, in-process /resume and in-process /fork never change claim ownership, never produce a self-deny and never leave a lease of the previous session_id.
  TEST: Claim foo(), run each of the four operations, then Edit foo(): allowed; the digest is re-injected with the 'supersedes' line; the lease table has no stale ids.
- **INV-CI-NONLIVE** In a repo without a valid live marker the hooks perform zero IPC and emit zero bytes (except the one-line WT note in a worktree of a live repo), and the MCP server advertises exactly one tool.
  TEST: Trace IPC and stdout of 200 hook invocations in a non-live repo: none, and p95 wall time <= 45 ms on Windows.
- **INV-CI-NO-REWRITE** PostToolUse handling and TXN close never write the author's working tree.
  TEST: A claim arrives between Pre and Post, and a Bash write lands in a held symbol: file bytes after the hook equal the bytes Claude wrote; the board shows the CS hold and the request.
