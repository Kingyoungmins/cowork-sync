# lifecycle — Define every way a peer enters, leaves, pauses, resumes, recovers and saves a live cowork session, and how the daemon reacts to the human's own git commands, so that (P1) no byte is lost across any lifecycle transition, (P2) every uncertain git state freezes the affected branch loudly instead of being published, (P3) one freeze state, one HEAD decision table, one REATTACH primitive and one preview/confirm step serve all lifecycle commands, (P4) unsupported situations (branch switch while live, linked worktrees, protected branches, local commits at join, downgrade) are refused with a precise message, and (P5) no decision compares clocks across machines. It applies the binding engine (INV-FF, SAVE, R3, R9, R10, state ref), data-handling, claude-integration, protocol, messaging-security and local-change-mgmt resolutions; where they leave a lifecycle gap or contradict each other, the rule says which way it resolves and open_questions flags it.

## v1 in scope
- Human-only lifecycle verbs as slash commands (disable-model-invocation) plus the same node CLI: start, stop [--keep-files], pause, resume, save, adopt, recover, end, uninstall [--purge], doctor (read-only), status (model-visible, read-only).
- Injective branch-to-ref encoding (enc(b): '%'->'%25', '/'->'%2F') for refs/cowork/*, refs/cowork-remote/*, refs/cowork-local/*, refs/cowork-archive/*; case-fold collision refusal.
- Ordered start preflight (git/node floors, repo shape, HEAD state, remote URL pinning, anonymity, custom-ref probe, filter round-trip, policy, IPC key ACL, volume/space, protocol floor, one live checkout per (url, branch) per OS user).
- Genesis of a branch's board/code refs with an empty-expect lease; JOIN per binding R9 with R3-first, HEAD == live base, preview and per-path opt-in; RESTART (crash, reboot, update, start-after-stop) with journal resolution including displaced .old files and the daemon's own adopt lock.
- One HEAD/epoch decision table (T1-T6) used by the loop, join, restart and resume; human `git pull`/ff-merge reconciled automatically (T2); local commits, resets, branch switches, bisect, rebase, cherry-pick, merge, stash frozen with a named way back.
- One FREEZE state with reasons {EPOCH, MASS, PAUSED, INCIDENT, VERSION, CONFIG, DISK}; /cowork pause = FREEZE(PAUSED) + hook-loader marker; /cowork resume handles each reason.
- Save = binding SAVE (existing live tree, checks, lease on the branch, never forced) with step-7 ordering on every host, R3(ii) completion, signing via commit-tree -S in the CLI, per-symbol attribution trailers, protected-branch refusal.
- U9 adopt per binding R10 plus staged apply at base-move boundaries and a single REATTACH primitive (used only by automatic adopt and the binding human-typed /cowork adopt).
- Stop: flush, durability, release/return/leave, PARK, CLEAN (default, sign-off) or --keep-files, state kept for RESTART; one live branch per clone; supported branch-switch path = stop, switch, start.
- Uninstall/disable/update: lease expiry, key-file/runtime loss shutdown with no working-tree writes, forward-only state migration, version handshake.
- Version skew: protocol.json floors checked before every push from v1.0, deterministic proto raise, checkpoint proto rule, no downgrade.
- Network timeouts and watchdog, wake handling, offline publish ordering; save/end/recover/stop-flush refuse while offline.
- Rewrite incident recover (displaced copy of the bad value first, empty-expect lease when the ref is gone) and /cowork end (archive ref + end op + lease-delete) as the only ref deletion path.
- Status surface without IPC: status.json heartbeat read by the hook loader, opt-in chained statusLine, OS notifications on freeze/offline/save-blocked/unadopted/incident.

## v1 refuse/defer
- Branch switch, detached HEAD, bisect, interactive rebase while live: v1 FREEZE(EPOCH) with the exact way back; supported path is /cowork stop (clean) -> git switch -> /cowork start. v2: automatic stop-and-park on switch.
- Live mode in a linked worktree, under .claude/worktrees, or when another linked worktree has refs/heads/<b> checked out: v1 refuse (adopt would move that worktree's HEAD under it). v2: per-worktree live mode.
- Shallow clones, partial (promisor) clones, sparse checkout / skip-worktree entries, core.splitIndex=true: v1 refuse at start (ancestry checks need history; sparse paths would be staged as mass deletions; adopt copies .git/index). v2: support with explicit path scopes.
- Repository root inside a cloud-sync folder (OneDrive, OneDriveCommercial, Dropbox, Google Drive, iCloud Mobile Documents): v1 refuse unless the human passes --allow-cloud-folder (shown in status) because a second sync engine locks and rewrites files (cloud-sync-folder-second-sync-engine).
- Join or start-after-stop with HEAD ahead of or diverged from the live base (unpushed local commits): v1 refuse 'push or move your local commits first'. HEAD behind: refuse with `git pull --ff-only` (join) or with `git reset --soft <H_adopt8>` (restart/resume after a backwards reset); cowork never moves the branch outside U9 adopt.
- Save to a branch the host rejects for direct pushes (protected branch, required PR, required status checks, required signatures without signing, GH013, pre-receive): v1 refuse with the host's message and 'go live on a feature branch and open the PR from it'. v2: save to a PR branch with Cowork-Saved-Live-aware merge-back.
- A human commit that changes live-changed paths and is pushed: R3 base move conflicts or pauses (VERIFIED lc/P5); v1 blocks saves and tells the committer to revert it on the branch (`git revert --no-edit <K> && git push`) and use /cowork save. v2: R3 per-path base = newest live blob equal to K[p] (see open_questions).
- Two live checkouts of the same (pinned URL, branch) by one OS user, or two live branches in one clone: v1 refuse naming the other checkout/branch.
- Branch rewritten or force-pushed so the live base is not an ancestor of the remote branch head (R3 case i): v1 blocks saves and base moves, live continues on the old base, humans told. v2: guided rebase of live onto the rewritten branch.
- Plugin downgrade (state ref meta.proto newer than the daemon) and peers below the board's minWriter: v1 FREEZE(VERSION) with 'update cowork-sync'. No read-only participation mode in v1.
- Divergent rewrite-recovery candidates (no candidate has the others on its first-parent chain): v1 refuse and require a human `/cowork recover --use=<oid>`.
- Headless syncing with no Claude session (login item, service): v1 only via the binding `/cowork start --human <minutes>` CLI lease. v2: background service.
- Automatic board rotation (new genesis without archive): v1 only through human /cowork end (archive first). v2: rotation command preserving open records.
- Fingerprint differences in core.autocrlf/core.eol between peers: allowed (shown in status only); the EOL canon makes stored blobs identical, so the protocol rule's join refusal on fingerprint mismatch is NOT applied (see open_questions). Filter drivers are refused only by the round-trip preflight, not by comparing command strings.
- Content-level reverts that leave no git signal (/rewind 'Restore code', stale editor buffer saves, VS Code 'Discard Changes', `git restore`/`checkout --` of a single path): not detected by lifecycle signals; owned by LCM-5 taint and the LCM-6 mass-change breaker (rewind-restore-code-reverts-teammates, stale-editor-buffer-reverts-peer-work). Lifecycle only marks the snapshot after a reflog/ORIG_HEAD change as git-op-caused.
- Signing saves with pinentry on Windows from a slash command (no TTY): implemented as commit-tree -S in the CLI process but NOT yet verified on Windows GPG4Win/ssh signing; until verified, a signing failure refuses the save.

## interfaces
- Slash commands (all disable-model-invocation: true) -> `node "${CLAUDE_PLUGIN_ROOT}/dist/cli.js" <verb> [args]`: start [--publish=all|none|<paths>] [--allow-cloud-folder] [--repin] [--human <minutes>], stop [--keep-files] [--discard-holds=<ids>] [--export=<dir>], pause, resume [--confirm=<id>], save "<summary>" [--sign] [--confirm=<id>], adopt [--confirm=<id>], recover [--use=<oid>] [--confirm=<id>], end [--force-absent] [--unsaved-ok] [--confirm=<id>], uninstall [--purge], doctor, status. MCP (model-visible): cowork_status only for lifecycle.
- Preview ids: 6-hex digest of the exact oids/paths shown in a preview; a --confirm whose id no longer matches current state is refused with a fresh preview (staleness guard, not an authentication secret).
- Refs (enc(b) = b with '%'->'%25', '/'->'%2F'): remote refs/cowork/enc(b)/{board,code}, refs/cowork/enc(b)/displaced/<oid12> (<=3), refs/cowork/probe-<peer8> (start probe, deleted after), refs/cowork-archive/enc(b)/<n> (END); local refs/cowork-remote/enc(b)/{board,code,branch}, refs/cowork-local/enc(b)/{state,holds,incident-<n>,retired-<n>}; the user's refs/heads/<b> (written only by REATTACH) and .git/index (written only by REATTACH).
- State ref meta (lifecycle fields): {live_base Hb, H_adopt, stash_expected, logs_head_size, orig_head, freeze_reasons[], snap_pre_freeze, save_blocked_reasons[], stop_mode (none|clean|keep-files), pinned_url, repo_identity (sorted root oids), probe_result, proto, peer_id, display}. Journal intents: apply (per-path tmp names), push (op ids), adopt {from, to, paths, sha256_temp_index, sha256_orig_index}.
- Files under `git rev-parse --git-path cowork/`: live (hook-loader marker), paused (hook-loader marker), peer, daemon.lock {pid, process start time, plugin version, instance id}, enc(b).index, tmp/ (.new/.old ring, adopt.index, save-<n>/ worktrees), status.json. Per-user cache CLAUDE_PLUGIN_DATA/repos.json [{gitdir, url, branch, peer8}] (never correctness state); CLAUDE_PLUGIN_DATA/runtime/<version>/; IPC key file (RULE IPC).
- Board ops emitted by lifecycle: join{display, plugin_version, plugin_sha, proto, config_fingerprint (display only), coauthor (opt-in)}, leave, seat_end, release, request_status returned (stop), health/freeze{reasons}, save{save_commit, saved_live, chain_base, symbols[]}, end{reason}, presume_absent (end --force-absent). Commits: genesis code commit (no parent, Cowork-Base), save commit S (no skip markers, Cowork-Saved-Live), base-move commits (binding R3).
- Consumes from other groups: R1 INV-FF check, R3 base move, R6 verifying writer, R7 snapshot, R8 loop, R9 join/restart/lost-state, R10 adopt conditions, LCM-5 taint, LCM-6 breaker, LCM-8 durability and PARK, LCM-11 ready trees, LCM-14 T0, LCM-17 candidate preference, data-handling FILTER preflight and canon/EOL save refusal, protocol governor slots and fold, messaging-security AUTH health and REF-TRUST, claude-integration lease/handshake and G1-G4.
- Hook I/O: SessionStart reports node presence, policy state and seat; the loader reads <gitdir>/cowork/{live,paused,status.json} with no IPC; freeze/offline/unadopted notices are additionalContext (once per episode) + systemMessage; Bash/PowerShell advisory deny covers lifecycle verbs and history-moving git verbs (claude-integration).
- OS notification helper (Windows toast via PowerShell, macOS osascript, Linux notify-send when present), <=1 per 30 min per reason.
- Evidence files: experiment <scratchpad>/sweep/lc/lc1.sh (+ lc1.log); full catalog JSON <scratchpad>/lifecycle_spec/spec.json (generator build.py).

## rules
- **LIFE-01** COMMAND AUTHORITY. Every lifecycle verb (start, stop, pause, resume, save, adopt, recover, end, uninstall) MUST exist only as a slash command with `disable-model-invocation: true` whose body runs `node "${CLAUDE_PLUGIN_ROOT}/dist/cli.js" <verb>` (never npx), and as the same CLI in a terminal. No MCP tool may perform a lifecycle verb; the only model-visible lifecycle surface is the read-only cowork_status. The claude-integration advisory PreToolUse(Bash|PowerShell) deny MUST include any command line that names dist/cli.js or `cowork` with one of these verbs. Any verb whose effect publishes, moves a branch or removes bytes from disk (start with local changes, save, adopt, recover, end, stop, uninstall --purge) MUST first print a preview and do nothing until the human re-runs it with the flag the preview prints (`--publish=...` or `--confirm=<6-hex preview id>`); the preview id is a digest of the exact oids and paths shown, so a confirm against changed state is refused with a fresh preview. pause and the marker part of resume MUST be implemented in the dependency-free hook-loader module so they work when core.js cannot load. Every board op and commit a lifecycle verb produces records actor 'human:<display>'.  _(covers: model-invocable-save)_
- **LIFE-02** IDENTITY, REF NAMES, ONE DAEMON, ONE LIVE CHECKOUT. (a) Every cowork ref uses enc(b) = branch name with '%' -> '%25' then '/' -> '%2F' (refs/cowork/enc(b)/{board,code}, refs/cowork-remote/enc(b)/*, refs/cowork-local/enc(b)/*, refs/cowork-archive/enc(b)/*); a name that fails `git check-ref-format` after encoding is refused. (b) At start, one read-only `git ls-remote <pinned url> refs/cowork/` lists existing cowork branches; if enc(b) case-folds equal to a different existing name, start refuses (case-insensitive ref storage on Windows/macOS). (c) peer_id is 128-bit random, created at first start and stored at <gitdir>/cowork/peer; the display name is chosen by the human at first start; neither is taken from the OS user. (d) Exactly one daemon per clone: <gitdir>/cowork/daemon.lock holds {pid, process start time, plugin version, instance id}; a starter that finds a live process with the same start time connects to it through the RULE IPC challenge instead of starting; otherwise it replaces the lock atomically (write temp + rename). (e) Live mode requires the main worktree: `git rev-parse --git-dir` equals `--git-common-dir`, the path is not under .claude/worktrees, and `git worktree list --porcelain` shows no linked worktree with refs/heads/<b> checked out. (f) Per OS user, one live checkout per (pinned URL, b): CLAUDE_PLUGIN_DATA/repos.json (a cache) lists {gitdir, url, b}; start refuses, naming the other checkout, when another listed gitdir has a live marker for the same (url, b) and a live daemon lock. (g) At most one branch per clone is live: /cowork start on b2 while b1 has a live marker refuses with 'stop b1 first'.  _(covers: clones-worktrees-identity, duplicate-daemon-same-clone, orphan-daemon-uninstall, worktree-isolation-gitlink-and-unmapped-edits)_
- **LIFE-03** START PREFLIGHT. /cowork start and /cowork doctor MUST run this ordered list in the daemon's own process environment; the first failure refuses start (doctor: reports) with the exact fix and nothing is written: 1) git >= 2.43.0 and node >= 20 (the SessionStart hook reports the hook-environment node; absence means no seat and start refuses). 2) Repo shape: non-bare; LIFE-02(e); `git rev-parse --is-shallow-repository` is false; no extensions.partialClone or remote.*.promisor; core.sparseCheckout is false and `git ls-files -t` shows no 'S' entries; core.splitIndex is not true; repo root not under %OneDrive%, %OneDriveCommercial%, a Dropbox/Google Drive root or ~/Library/Mobile Documents unless --allow-cloud-folder. 3) HEAD is symbolic to refs/heads/<b>; the LIFE-06 marker set is empty; no unmerged entries; no .git/index.lock. 4) Remote pinning: r = branch.<b>.remote (default origin); `git remote get-url r` must equal `git remote get-url --push r` (both after insteadOf/pushInsteadOf); the URL and the repo identity (sorted root-commit oids of the fetched refs/heads/<b>) are pinned in state meta and used for every daemon fetch/push instead of the remote name; the anonymous-readability refusal (REF-TRUST 5) runs on the pinned URL; once per (clone, URL) a probe on refs/cowork/probe-<peer8> checks create with empty-expect lease, leased update and leased delete (result cached in state meta). 5) The data-handling FILTER preflight (driver discovery, round-trip, idempotency, canary) passes for every filtered path; only its result decides (config_fingerprint, including core.autocrlf/core.eol, is published for display and never compared for refusal). 6) POLICY-DETECT state is not NO-HOOKS. 7) RULE IPC key file ACL is user-only. 8) <gitdir>/cowork/tmp is on the worktree's volume and that volume has >= 1 GiB free. 9) If a board exists, protocol.json minReader <= P and minWriter <= P (P = this daemon's protocol); if a state ref exists, its meta.proto <= P. 10) LIFE-02(b), (f), (g). Then: no board -> LIFE-04 GENESIS; board but no state ref -> LIFE-05 JOIN; state ref -> LIFE-10 RESTART. While live, a later change of the configured URL, repo identity, filter preflight result or policy state sets FREEZE(CONFIG) until restored or until a human `/cowork start --repin` passes steps 4-6 again.  _(covers: remote-url-drift, filter-passthrough-leak, secret-filter-fails-open-in-daemon-env, secret-filter-passthrough, peer-normalization-secret-leak, policy-fail-open, cloud-sync-folder-second-sync-engine)_
- **LIFE-04** GENESIS (first peer on a branch). When refs/cowork/enc(b)/board is absent and LIFE-18(c) finds no END archive that this clone's state still points into: require HEAD == Hr (the freshly fetched refs/heads/<b>); if HEAD is behind, refuse with `git pull --ff-only`; if ahead or diverged, refuse with 'push your local commits first'. Compute the LIFE-05 preview with A = tree(HEAD) and apply its confirmation rule. The genesis code commit L0 = `commit-tree tree(Hb)` with NO parent, trailers `Cowork-Base: <Hb>`, `Cowork-Proto: <P>`, and the live markers '[skip ci] ***NO_CI***' + 'skip-checks: true'; the genesis board commit has L0 as its only (last) parent, ops = [join], and protocol.json defaults. Push board and code mirror with `--force-with-lease=refs/cowork/enc(b)/board:` and `--force-with-lease=refs/cowork/enc(b)/code:` (empty expect = must not exist; VERIFIED lc/P2: the second creator is rejected). On rejection, refetch and run JOIN. Definition used everywhere: live_base(L) = the Cowork-Base value of the newest commit on L's first-parent chain that carries the trailer; genesis and base-move commits carry it, and branch commits (including save commits) MUST NOT, so the walk always ends at or before genesis.  _(covers: join-or-restart-seeds-revert)_
- **LIFE-05** JOIN (board exists, no state ref for b), applying binding R9 JOIN. Order: fetch board -> INV-FF check -> if Hr != live_base(TIP) run R3 first (a not-yet-joined daemon may publish the base move; the lease admits one; having no apply journal, it computes R3's 're-introduces content the live chain removed' guard from the live chain's own diffs since Hb only) and refetch; an R3 conflict or rewrite refuses join with the conflicting paths. Then require symbolic HEAD = refs/heads/<b> and HEAD == Hb = live_base(TIP); HEAD an ancestor of Hb -> refuse with 'run `git pull --ff-only`, then /cowork start'; ahead or diverged -> refuse 'push or move your local commits first'. Set A := tree(HEAD), never TIP or any other tree. Snapshot S_disk per R7 (U10 scope, so pre-existing admitted untracked files count). PREVIEW (shared with GENESIS and with RESTART after stop): N paths that will change on disk (diff A->TIP), M local changes that would be published (diff A->S_disk, each with size and whether it is a new untracked file), and the list of present-but-unshared files with reasons. If M > 0, nothing is written or published until the human re-runs with --publish=all|none|<paths>; unconfirmed paths become park-join PIN records in the hold registry (kept on disk, masked, mirrored). The first apply runs through R6 and LA_C := TIP only after it; if nothing was opted in, the first publish asserts OUT == tree(TIP). The join op is published in the first board push.  _(covers: late-join-wrong-merge-base, join-or-restart-seeds-revert, naive-push-reverts-unapplied-paths)_
- **LIFE-06** EPOCH OBSERVATION AND THE ONE HEAD DECISION TABLE. At loop step 0 and in join, restart and resume, the daemon reads, with GIT_OPTIONAL_LOCKS=0 and LC_ALL=C and paths from `git rev-parse --git-path`: symbolic HEAD, HEAD oid, refs/stash oid or absence, markers {MERGE_HEAD, CHERRY_PICK_HEAD, REVERT_HEAD, REBASE_HEAD, AUTO_MERGE, BISECT_LOG, BISECT_START, rebase-merge/, rebase-apply/, sequencer/}, unmerged entries in the user's index, .git/index.lock (existence, mtime), byte size of logs/HEAD, ORIG_HEAD oid. Expected E = {symref refs/heads/<b>, oid H_adopt, stash stash_expected, no markers, no unmerged}. logs/HEAD growth and ORIG_HEAD change never freeze by themselves: they mark the next snapshot's unobserved delta as git-op-caused for LCM-5 taint and the LCM-6 breaker (catches `reset --hard` with HEAD unchanged); the daemon re-baselines both after its own REATTACH (VERIFIED lc/P1: update-ref on the checked-out branch appends to logs/HEAD). index.lock present -> that iteration only fetches; present with the same mtime for >= 30 s -> one notice 'a git command holds .git/index.lock (for example a commit message editor); sync waits'; the daemon never deletes it (LIFE-10 own-adopt case excepted). Table: T1 E holds -> normal. T2 symref ok, no markers, stash ok, HEAD != H_adopt, HEAD a branch commit with H_adopt <= HEAD <= Hr (human pull / ff-merge; VERIFIED lc/P4: a pull of disjoint paths succeeds and keeps live bytes) -> FREEZE(EPOCH) until live_base(TIP) >= HEAD (R3, which a frozen daemon may run), then ONE state update sets H_adopt := HEAD and A[p] := TIP[p] for every p in diff(old H_adopt, HEAD) with clean(disk[p]) == TIP[p], lifts EPOCH, and R10 continues HEAD -> live base. T3 symref ok but HEAD not <= Hr (commit, amend, rebase, merge, cherry-pick) -> FREEZE(EPOCH); immediately compute diff(H_adopt, HEAD) intersected with diff(Hb, tree(LA_C)) and with ACTIVE/PARKED registry paths, and if non-empty tell the human and every live seat at once: 'commit <K8> contains teammates' unsaved live changes (or held change R<id>) in <paths>; pushing it will block saves for the whole team; undo with `git reset --soft <H_adopt8>` and use /cowork save, or commit only other files'; exits are a push that makes HEAD <= Hr (then T2) or HEAD returning to H_adopt. T4 symref ok, HEAD < H_adopt (reset backwards) -> FREEZE(EPOCH); the notice and resume both say 'move your branch back with `git reset --soft <H_adopt8>` (files are not touched)'; cowork itself never moves the branch here (U9 allows HEAD/index writes only for safe adopt). T5 symref != refs/heads/<b> (switch, checkout <oid>, bisect, stopped rebase) or any marker or unmerged entry -> FREEZE(EPOCH); the notice names the operation and the way back (`git switch <b>`, `git bisect reset`, `git rebase --continue|--abort`, `git cherry-pick --abort`, `git merge --abort`); resume refuses. T6 stash != stash_expected -> FREEZE(EPOCH); notice 'run `git stash pop` to continue, or /cowork resume to restore the team version and keep your stash'. EPOCH lifts automatically only when the table returns T1 (or T2 completes) and the LCM-6 unobserved-delta condition holds.  _(covers: branch-switch-publishes-other-branch, worktree-reset-commands-broadcast-revert, user-git-ops-broadcast-as-revert, git-ops-publish-team-revert, human-git-mass-revert, local-git-ops-propagate-as-reverts, bash-git-verbs-revert-and-markers, in-progress-ops-not-paused-conflict-markers-broadcast, b-bypass-revert-of-unsaved-peer-work, head-drift-after-pull-or-save, held-hunk-escapes-via-branch-commit, conflict-markers-enter-live-ref)_
- **LIFE-07** ONE FREEZE STATE. A branch loop has one FREEZE state holding a set of reasons from {EPOCH (LIFE-06), MASS (LCM-6 breaker), PAUSED (/cowork pause), INCIDENT (R1 rewrite), VERSION (LIFE-16), CONFIG (LIFE-03 item changed while live), DISK (free space on the worktree volume < 256 MiB; lifts automatically at >= 512 MiB)}, stored in state meta so it survives restart; entering EPOCH or MASS also records snap_pre_freeze := the last state snapshot tree taken under the expected epoch. While any reason is set: no daemon-initiated working-tree write (apply, PARK, RESTORE, disk repair, CLEAN), no code publish, no REATTACH, no save from this peer, and new claims stay tentative and local (the gate still enforces foreign claims from the last fold); allowed: fetch and fold, R3 base moves (they read no working-tree bytes), human-typed /cowork resolve commands, and board-only pushes of freeze/health events, answers, releases and hold-registry mirrors. INCIDENT additionally forbids every push on that branch (binding R1). Ready trees captured before the freeze (LCM-11) stay referenced from state and publish after it lifts. Entering a freeze (or adding a reason) posts ONE board event {peer, reasons}, shows the human a systemMessage and status line and an OS notification (<= 1 per 30 min per reason), and gives each live seat on this clone one additionalContext per episode: 'cowork-sync is paused for this repo (<reason>). Edits stay on this PC and are checked before they are shared when the pause ends.' /cowork pause sets PAUSED and writes <gitdir>/cowork/paused, which the hook loader checks before any IPC and then exits 0; only /cowork resume removes it, and the board shows the peer as 'not coordinated' meanwhile.  _(covers: breaker-freezes-publish-not-apply, disk-full-or-locked-file-partial-apply-broadcast, mcp-or-daemon-death-fails-open-and-stuck-fences)_
- **LIFE-08** RESUME. /cowork resume handles each freeze reason and never clears a reason it cannot justify. PAUSED: remove the marker and continue with A unchanged; edits made while paused are ordinary unobserved local edits, subject to LCM-5 taint, the LCM-6 breaker and the B1 publish gate. EPOCH or MASS: run the LIFE-06 table; T5 refuses with the way back; T3 refuses ('push the commit or undo it'); T4 refuses with `git reset --soft <H_adopt8>`; T2 and T6 proceed. Then, only for paths p where clean(disk[p]) differs from snap_pre_freeze[p] (the state snapshot recorded in meta when EPOCH/MASS was entered; unchanged paths keep A[p]), rebuild A[p] with the binding LOST-STATE rule (A[p] := newest blob of p on TIP's first-parent chain, bounded by the live base or 500 commits, equal to clean(disk[p]); unmatched p -> A[p] := TIP[p] and the bytes become a 'restart' hold, neither published nor overwritten), so paths a git operation reverted get the team version back and genuinely new bytes are held; accept the current refs/stash as stash_expected; re-run LCM-5 taint over the whole batch; clear EPOCH/MASS; print the restored and held paths and, for T6, 'your stash@{0} still contains teammates' live changes; review it with `git stash show -p` instead of popping it while live'. INCIDENT, VERSION, CONFIG and DISK: resume refuses and names the only exit (/cowork recover; update cowork-sync; restore the remote URL or `/cowork start --repin`; free disk space).  _(covers: worktree-reset-commands-broadcast-revert, breaker-freezes-publish-not-apply, local-git-ops-propagate-as-reverts, human-git-mass-revert)_
- **LIFE-09** BRANCH MOVES BY HUMANS AND SAVE-ONLY PATHS. While live, refs/heads/<b> on the remote moves only by a cowork save (LIFE-11) or by any other push (a teammate's plain push, a PR merge, a bot, this human's commit + push); every daemon treats the latter as binding R3 (merge into live with explicit base, guards, conflict blocks saves). Local human pulls and commits are classified only by LIFE-06 (T2/T3). The save-only set (.gitattributes, .cowork/config.json, the EXEC-SURFACE quarantine set, LFS, generated/excluded, custom-merge-driver, >= 50 MiB, gitlink and symlink paths) can never enter a cowork save, because tree(S) is exactly a live tree and live never publishes those paths; they reach the branch only through a human commit of exactly those paths (`git commit -- <paths>`) and push, which is disjoint from live-changed paths and merges cleanly in R3 (VERIFIED lc/P5: disjoint commit rc=0, overlapping commit rc=1). ## numbers
- index.lock: iterations only fetch while it exists; one notice after 30 s with the same mtime (unifies R8's 10 s wait and LCM-6's 30 s stale report; a commit-message editor legitimately holds the lock for minutes, so the daemon reports and never deletes).
- Network: http.lowSpeedLimit=1000 B/s for http.lowSpeedTime=10 s (VERIFIED in sweep/lifecycle/blackhole.js that a 5 s setting fails a hung fetch in 5 s while the default hung past 25 s); SSH ConnectTimeout=10, ServerAliveInterval=5, ServerAliveCountMax=3; hard watchdog 45 s per network command (above the slowest normal push of the 1.3 MB file, below the 60 s claim self-guard).
- Suspend gap > 5 s (Δwall − Δmono, same machine) triggers the wake path (protocol 10b); offline = no successful fetch for > 30 s (AUTH rule).
- Save: final sync round <= 2 governor windows (each <= G + (N−1)·S = 19 s for 4 peers); <= 3 R3-first retries; <= 20 candidates; save.check 300 s per candidate and 15 min total; worktree add 0.49-0.51 s and remove about 0.16 s for 3,001 files + the 1.34 MB file (VERIFIED, atomicity lens x10/x5); attribution computation capped at 10 s; <= 300 Cowork-Symbol trailer lines.
- REATTACH: index rename retried 5 x 100 ms on EACCES/EPERM (Windows readers hold .git/index briefly), else roll back and retry next loop.
- Stop: flush waits at most 2 governor windows, hard cap 60 s; a seat counts as mid-turn with hook traffic in the last 60 s and no Stop since its last UserPromptSubmit (binding seat rule); the issuing seat is exempt.
- Disk: start requires >= 1 GiB free on the worktree volume; FREEZE(DISK) below 256 MiB, lifted at >= 512 MiB (hysteresis prevents flapping; the 1.3 MB file adds about 1.3 MB of loose objects per changed snapshot).
- Lease and shutdown: 2 min without a lease -> no apply/push, 10 min -> exit, key-file and runtime presence checked every 30 s (binding claude-integration and RULE IPC).
- Status: heartbeat considered stale after 3 poll intervals (7.5 s active, 30 s idle at the binding 2.5 s / 10 s polls); OS notifications at most 1 per 30 min per reason.
- Recovery: LOST-STATE and resume rebuild search bounded by the live base or 500 first-parent commits (binding); at most 3 displaced refs per branch (binding REF-TRUST).
- Durability: `-c core.fsync=committed,reference,index -c core.fsyncMethod=batch` on state, registry and REATTACH writes (local git 2.55 docs: default is 'committed,-loose-object', which hardens neither loose objects nor references).
- Ghost threshold for end and proto raising: no op in the last K_evict = 200 board commits (binding protocol).

- Engine SAVE steps 5-6 (push --atomic with leases on branch, code and board) vs protocol (9) ('the protocol never needs atomic'; board is the authority). LIFE-11 applies step 7's ordering on every host: push only the branch, then R3(ii) completes the live side in the next slot (its base-move commit is byte-identical in shape to the binding Ls). This reinterprets a binding step under P3; engine group please confirm.
- Genesis shape (LIFE-04): L0 has no parent and carries Cowork-Base; save commits must never carry Cowork-Base. Engine group please confirm this matches 'the base recorded in the session's first live commit'.
- Convergence rule says 'join REFUSES a peer whose config_fingerprint differs'; the EOL rule says 'no join refusal on autocrlf mismatch'. LIFE-03 resolves: refusal only by the filter round-trip preflight; autocrlf/eol differences are display-only, and the convergence claim is byte-identical only for peers with equal autocrlf/eol (stored blobs are identical for all). Protocol group please align the convergence text.
- EPOCH_BASE is defined in data-handling as 'the join commit or the last save commit; changes only at save/adopt', which ignores R3 external base moves. LIFE-09 defines it as live_base(LA_C), changing at every base move. Data-handling group please confirm; it also means 'a .cowork/config.json change takes effect at the next save' is really 'at the next base move', reached by a human commit of only that file plus push.
- Engine converged-path rule needed: A[p] := TIP[p] whenever clean(disk[p]) == TIP[p] at apply, not only for written paths. LIFE-06 T2 applies it at the reconcile transition; without it in general, paths that arrive on disk by a human pull keep a stale A and INV-CONVERGE (snap == A == tip) fails.
- v2 proposal for R3 (engine): when the moved branch head contains a human commit K whose K[p] equals some blob of p on TIP's first-parent chain since Hb, use that blob as the per-path merge base (synthesized base tree), which makes the common `git commit -a && git push` of live content merge cleanly instead of blocking saves (lc/P5 shows base=Hb conflicts). Deterministic and ancestry-free, but it treats a deliberate commit of an older live version as 'no intent to revert'.
- Protocol data model still has a `reset{code_commit}` op and 'a code-pointer move that does not descend ... is legal only with a reset op (save)'. Under INV-FF saves are fast-forwards, so that exception should be deleted; the only non-FF board change is human `/cowork recover`. LIFE-18 also adds an end{reason} op and refs/cowork-archive/<enc b>/<n>; protocol group please add them. The save op lists symbols, and each holder's daemon releases its own covered claims per protocol (11)(b) because only it knows its seats' turn state.
- Checkpoint writing under version skew (LIFE-16 d) changes protocol's 'checkpoint differs from own fold -> P2 alert, read-only': cross-proto differences must not alert, otherwise every rolling upgrade puts newer daemons read-only.
