# F10 — Revert my own change-set (`/cowork revert <cs_id|last>`)

**Status:** proposal, spec delta against glossary rev 2.4 (merged as the next free glossary revision section; the number is assigned at merge, because 12-visualizer §9.2 already claims §28). **Ids:** the requirements keep their `FEAT-F10-NN` ids when merged; chapter rule ids (HLD-, CCI-, COO-, UX-) are assigned at merge, so parallel proposals cannot collide (F14 also proposes UX-32/UX-33). **Protocol change:** none (no op, op field, trailer, ref or board file is added; the result is an ordinary human CS). **Touches:** 00 §6, §9, §15, §20 · 05 §2 "observed change", HLD-26, HLD-50 item 3, one new rule (Algorithm REV) · 06 `cowork_show` · 07 `T-WAKE_RECAP` (one new line), new `T-SHOW_UNDO.*` (RULES unchanged) · 08 §2.6 · 09 §2 · 10 §1.3, §3.4, §3.8, §3.9, §3.19 · 11 TST-25, §7. 12-visualizer: no change.

## 1. Purpose

A Claude change-set (CS) is published at every passing edit checkpoint (glossary §27.1), and a wake turn can change code while its human is away (S5). When this user dislikes such a change after it was shared, the host's `/rewind` "Restore code" (and `git checkout`, or Write of an old copy) puts back whole old files: that overwrites every line a teammate added since, and HLD-27 then turns the overwrite into `revert` hold records the human must sort out. F10 gives one safe undo: **remove exactly this peer's own CS from the live tree with a reverse 3-way merge, keeping every line a teammate wrote later**, and publish the result as one ordinary human CS that passes every existing gate. Reverting a teammate's CS is out of scope (that is F11; 10-product §1.3 stays as decided). F10 is not `/cowork resolve <id> --restore` or `cowork_resolve(id,"restore")`: those put a *held* version back from a hold record (HLD-17); F10 takes an already *shared* change out of the live tree. Nothing in the spec does that today (`undo` is refused, 10 §1.2; the revert detector only catches whole-file restores, HLD-27).

## 2. User-visible behaviour

### 2.1 Commands

| Surface | Form | Kind |
|---|---|---|
| Human verb | `/cowork revert <cs_id>\|last [--confirm=<id>]` | acting (SEC-25 evidence), preview/confirm, exit 0/1/2 per glossary §15 |
| Human view | `/cowork show <cs_id>\|last --undo [--json]` | read-only; the same computation, no write |
| Claude view | `cowork_show(<cs_id>)` on a CS of this peer | MCP result ≤ 8,000 chars: CS summary + undo view; Claude applies it with Edit |

- `<cs_id>` is a full `cs_id` (`<seat_id>/<turn-seq>` or `<peer_id>/human/<n>`, glossary §3) or a unique prefix of ≥ 6 characters among the CSs inside the revert window (§2.6); more than one match → `AMBIGUOUS_ID` with ≤ 5 candidates. A `cs_id` names one CS only within one `(peer_id, epoch)`: HLD-33 keys CS identity by `(Cowork-Writer peer_id, epoch, cs_id)` because a human counter may restart in a new epoch. When the id occurs under more than one epoch of this peer inside the window → `AMBIGUOUS_ID`, candidates shown as `<cs_id>@<epoch8>` (the first 8 characters of the epoch in `Cowork-Writer`), and that qualified form is accepted as `<cs_id>`.
- `last` = the newest **closed** CS of this peer (by board order of its newest commit, or by local close order for a CS not yet in the live chain), whatever its state: open CSs (a running turn, a human edit burst) are ignored because they are still being made. If that CS is not fully shared yet (ready, or held), `last` refuses with `RF_REVERT_NOT_SHARED`; it never skips to an older CS, so typing `revert last` twice never walks back through history. The trailer state is not used to decide "closed": a CS fully published by edit checkpoints has only `state=checkpoint` trailers (05-holds §8 item 16), so closure comes from the local CS table. A revert CS is a CS too, so `revert last` after a revert has been shared previews "revert of a revert" (a redo); before it is shared it refuses.
- The verb name is `revert`. `undo` stays refused with `RF_UNKNOWN_VERB` (10-product §1.2).

### 2.2 Which CSs qualify

A CS qualifies only if every commit carrying its `Cowork-CS` trailer is on TIP's first-parent chain, is written by this peer in one epoch (the CS's own; §2.1), and is listed in this peer's provenance journal `prov/<enc(b)>.jsonl` (HLD-25, 14 days). This covers this PC's seat CSs (`<seat_id>/…`, ended seats included), its human and `recovered` CSs (`<peer_id>/human/<n>`), and `origin=wake` CSs. A CS that a save already carried still qualifies: the revert changes the live tree and the next `/cowork save` carries it (the live chain is never reset at save, INV-FF).

### 2.3 Preview, confirm and report (human-facing, 6 languages; en shown)

Preview (exit 1, nothing changed), in this order, ≤ 50 lines per list plus "and k more" (digest always over the full lists; 10-product §3.4):
1. `UI_REVERT_HEAD`: "Revert {cs} by {name} ({origin}, {k} commits): {n} files change back; lines teammates changed later stay." Plus `UI_REVERT_OF` "This change-set itself reverted {cs0}." when the target is a revert CS.
2. Per changed path `UI_REVERT_PATH`: "{path}: −{del} +{add} lines" (binary: "{path}: restored / deleted").
3. Per kept hunk `UI_REVERT_KEPT`: "{path} lines {a}-{b} stay: changed later by {names}". `{names}` (≤ 3) are attributed by line, not by path: the writers of journal entries after the CS's last commit on p whose `add` hashes (HLD-25) include a non-trivial line of the kept region's current text; this peer renders as `UI_REVERT_KEPT_YOU` ("you"). When no line matches (the later change only deleted lines, or changed only trivial or whitespace lines), `UI_REVERT_KEPT_ANON` "{path} lines {a}-{b} stay: changed later" names nobody, so no teammate is named for lines they did not write.
4. Per skipped path `UI_REVERT_SKIP` with keyed `{REASON}`: `MIXED` "shared one commit with your change-set {cs2}; it cannot be separated", `BUSY` "has unshared or held changes on this PC; run /cowork done or resolve them first", `FILE_CHANGED_LATER` "is a whole-file change (created, deleted, binary or file mode) that was changed again later; left as is", `RENAME_PAIR` "was renamed together with {path2}, which is skipped; both stay as they are", `NOT_LIVE` "is no longer shared live", `TEAMMATE_LINE` "would remove or re-add a teammate's line".
5. Predictions: `UI_REVERT_WOULD_HOLD` "{path}: inside {holder}'s held {label}; the whole revert stays on this PC until they release it" (B1 → K6), `UI_REVERT_WOULD_BREAK` "{sym} is still used in {path}; the revert would be held as a broken dependency unless that use goes too" (T0 → K7).
6. `UI_CONFIRM_LINE` with `--confirm=<6 hex>`.

Slash mode (cap 4,000, 10-product §3.3, UX-03): items 1 and 6 are never cut; when the body does not fit, list 2 is cut first, then 3, then 4, then 5, each ending with "and k more", followed by `UI_TRUNCATED_SLASH` with the terminal command. The preview id still digests the full lists (10 §3.4), so a confirm typed from a truncated preview writes exactly what the full preview lists.

After a matching confirm: `REVERT_REPORT` "Reverted {of} as {cs} ({n} files; {kept} hunks kept). It is shared like any edit of yours." Exit 0.

### 2.4 Claude path (undo view)

For a `cs_id` of this peer, `cowork_show` returns (template owner 07, en/ko): `T-SHOW_UNDO.head` "{cs} by {name} ({origin}): undo diff against this PC's current files ({n} files):", then per path a unified diff (`-U3`, stored form, current → reverted, the same computation as the verb but with `ours` = the current disk, §3 step 4), then the kept hunks and skipped paths as one line each, then `T-SHOW_UNDO.foot`:
- en: `To undo {cs}, apply the hunks above with Edit, exactly. Kept hunks stay: those lines were changed again later. Do not restore whole files (Write, /rewind, git checkout): that overwrites teammates' lines. This user can also run /cowork revert {cs}.`
- ko: `{cs} 를 되돌리려면 위 hunk 를 Edit 로 그대로 적용합니다. 유지 표시된 hunk 는 나중에 다시 바뀐 줄이라 그대로 둡니다. 파일 전체 복원(Write, /rewind, git checkout)은 팀원의 줄을 덮어쓰므로 하지 않습니다. 사용자는 /cowork revert {cs} 로도 되돌릴 수 있습니다.`

Over 8,000 chars: whole paths are dropped from the end and `T-SHOW_UNDO.trunc` "{k} more files not shown; after applying these, call cowork_show({cs}) again (applied hunks no longer appear)". The view diffs only text paths whose undo is a change inside an existing file. Every other path gets one line `T-SHOW_UNDO.human` "{path}: {kind}; this user can do it with /cowork revert {cs}", `{kind}` ∈ delete the file the change-set created, re-create the file it deleted, binary, file mode, filtered (stored form never smudged, never diffed): Edit can neither create nor delete a file, and a whole-file Write is what the foot forbids. For another peer's CS, `cowork_show` gives the summary only plus `T-SHOW_UNDO.notown` "Only {name} can revert this change-set." An unknown id stays `{ok:false, code:"UNKNOWN_ID"}` (06 §3.16.3). Claude learns its own cs ids from `cowork_checkpoint`'s result (`{cs_id, …}`), from `T-WAKE_RECAP`, or from an id the user pastes from `/cowork log`. The Edits Claude makes are its own seat CS: observed (HLD-26), claim-gated (G1), wake-limited (S5), edit-checked and B1/T0-gated as usual.

### 2.5 Refusals (exit 1; two-line form of 10-product §3.4)

| Situation | Code | `next:` |
|---|---|---|
| CS written by another peer | `RF_REVERT_NOT_OWN` | "(none: only {name} can revert it, with /cowork revert {cs})" |
| CS still open (turn running, or human CS not yet closed) | `RF_REVERT_OPEN` | `/cowork done` (human CS) or "(none: wait for the turn to end)" |
| CS closed but (partly) unpublished: ready (waiting for its push) | `RF_REVERT_NOT_SHARED` | "(none: it is being shared now; run the same command again in a minute)" |
| CS closed but (partly) held as a PIN/PATCH record | `RF_REVERT_NOT_SHARED` (param `hid`) | `/cowork show {hid}` (its footer lists the record's actions; never a bare `--discard`, which would also drop every CS bundled onto that PIN, HLD-49) |
| `<cs_id>` matches CSs of more than one epoch, or a prefix matches several CSs | `AMBIGUOUS_ID` | the candidates (`<cs_id>@<epoch8>` where needed) |
| Commits not in the 14-day journal window | `RF_REVERT_TOO_OLD` | "(none: older than 14 days; ask Claude to undo it with an ordinary edit)" |
| No qualifying CS for `last` | `RF_REVERT_NO_LAST` | `/cowork log` |
| > 2,000 paths, or > 500 merge-file runs needed | `RF_REVERT_TOO_BIG` | "(none: ask Claude to undo it file by file with cowork_show)" |
| Every path skipped or already reverted | `RF_REVERT_NOTHING` | `/cowork done` when a path was skipped as `BUSY` because of the open human CS; else `/cowork show {cs} --undo` |
| Any FREEZE reason set (glossary §8) | `RF_REVERT_FROZEN` | the freeze headline's next command |
| Writer answered LOCKED, DEFERRED, COLLISION, PHANTOM or FROZEN | `RF_REVERT_WRITE_FAILED` | `/cowork revert {cs}` (retry; nothing was written) |
| Writer MISMATCH, or recomputed preview differs | `PREVIEW_STALE` | fresh preview |
| Unknown id | `RF_SHOW_UNKNOWN_ID` | `/cowork log` |

Publish pauses (`OFFLINE`, `AUTH`, `VERSION`, `NONRETRYABLE`) do not refuse: the revert CS waits like any CS.

### 2.6 Numbers (new glossary §20 row "Revert")

Window: the provenance journal (14 days, HLD-25). ≤ 2,000 paths per revert; ≤ 500 `merge-file` runs per computation (paths unchanged since the CS need none, §3 step 4a); computation in a daemon worker, ≤ 30 s, then `RF_REVERT_TOO_BIG`. Lists ≤ 50 lines; slash output ≤ 4,000; `cowork_show` ≤ 8,000. `cs/<enc(b)>.reverts.jsonl` kept 14 days.

## 3. Algorithm REV (new 05-holds rule, id assigned at merge)

Input: target `t`, mode `verb` or `view`. All git work through runGit (glossary §18), in memory except the confirmed write: `merge-file -p` prints to stdout and nothing in steps 1–7 writes an object (glossary §26.1 W6).
1. **Resolve** `t` (§2.1). **Locate** `C(t)`: journal entries whose `cs_ids` contain `t`, in first-parent order, restricted to one `(peer, epoch)`: the epoch named by `@<epoch8>`, else the only epoch under which `t` occurs in the window. The epoch is read from each commit's `Cowork-Writer` trailer (the journal's `writer` keeps only the `peer_id`, HLD-25). The same `cs_id` under another epoch is another CS (HLD-33), so an unqualified `t` found under two epochs is `AMBIGUOUS_ID` (§2.1). None: one `rev-list --first-parent -F --grep='Cowork-CS: <t> '` over the live chain decides `RF_REVERT_TOO_OLD` (found) or `RF_SHOW_UNKNOWN_ID`. Any `c` with a writer ≠ this peer → `RF_REVERT_NOT_OWN`. `t` in the open-CS table → `RF_REVERT_OPEN`; `t` in a ready pair or in a non-terminal record's `cs_ids` → `RF_REVERT_NOT_SHARED`.
2. **Paths** of `t` in `c`: its `Cowork-CS-Paths`, or, without one (> 256 paths), every path of `diff(parent(c), c)` (HLD-37: a CS without a path list covers every path of its commit). A path is `MIXED` if in some `c ∈ C(t)` that changes it another `Cowork-CS` of `c` also covers it (by its list or by having none). **Rename pairs:** paths that `diff -M` of some `c ∈ C(t)` against its first parent (runGit, `--no-ext-diff --no-textconv`, glossary §18) pairs as one rename are one unit in steps 3–7: when either side is skipped for any reason, the other is skipped as `RENAME_PAIR`, so a partial revert never leaves both the old and the new file.
3. **Path guards.** Not `LIVE` now → `NOT_LIVE`. Verb mode only: `p` in an open or unpublished CS, under a non-terminal record, `A[p] ≠ TIP[p]`, or `¬DISK_EQ(p, A[p])` → `BUSY` (so in verb mode `ours` = `TIP[p]`, as the feature statement requires).
4. **Reverse 3-way**, `ours := S_disk[p]`, then for each `c ∈ C(t)` changing `p`, newest first, with `before = parent(c)[p]`, `after = c[p]`:
   a. `ours == after` (nobody touched it since) → `ours := before` (a file the CS created is deleted, a file it deleted is restored; no process);
   b. else if a side is `ABSENT`, the path is binary (DAT-04), or the mode differs → `FILE_CHANGED_LATER`, skip the whole path;
   c. else `git merge-file -p --object-id ours after before`; rc 0 → `ours := out`; rc > 0 → `ours :=` the same run with `--ours`, and each conflict region becomes a kept hunk (`CHANGED_LATER`). Conflict markers are never written anywhere.
5. **Taint backstop.** On `diff(S_disk[p], ours)`, D2's predicate (05 §3.6 step 3, same journal) restricted to lines outside the CS's own journaled sets (the union over `C(t)` of `paths[p].add` for removed lines, `.del` for re-added ones): such a non-trivial line journaled `add` (removed) or `del` (re-added) by a writer ≠ this peer → whole path `TEAMMATE_LINE`. Steps 4a–4c only remove lines the CS added and re-add lines it removed, so this never fires on a correct run; it guards the merge, not the user, and costs no process.
6. **Predict** (preview only, verb mode): REG `gate()` of the result hunks on the current claim view → `UI_REVERT_WOULD_HOLD`; the 04-regions edit-check entry point (HLD-67 checks 1–3 and check 4's label-count part, the checks T0 shares: a restored function that a teammate has since re-added elsewhere raises the label count) → `UI_REVERT_WOULD_BREAK`. Because `BUSY` guarantees `A[p] = TIP[p]` and `DISK_EQ(p, A[p])` on every result path, the merged tree `merge-tree --merge-base=A R_rev TIP` is TIP with the result blobs on those paths, so the check is fed the result buffers and TIP's blobs directly; no tree or object is written. Check 4's shrink part and T0's shrink guard do not fire on a revert-written path (HLD-50 item 3 edit, §8), so a revert that removes most of a file, or deletes a file the CS created, is not predicted or held as K7.
7. Result `R_rev` = the paths with `ours ≠ S_disk[p]`; empty → `RF_REVERT_NOTHING`.
8. **Write** (verb confirm): recompute 1–7; preview id = LIF-02 digest over `t`, the oids of `C(t)`, and per path `(S_disk[p], R_rev[p])` plus the kept and skipped lists; mismatch → `PREVIEW_STALE`. `hash-object -w` each result, then one `writeLocalGroup` (all or none; `expected` = the digested disk blob, target = result or `DELETE`, human evidence). On `WRITTEN`: open a new human-class CS `<peer_id>/human/<n>` (HLD-33) whose members are exactly these paths, close it at once (HLD-40 "human close"; its capture records `R[p]` = the written result blobs), mark these writes as revert-attributed for T0's shrink guard (HLD-50 item 3) until that CS is published (a hold keeps the mark, so a K6 PIN that auto-publishes on release, HLD-52, does not then fail T0's shrink guard), append `{cs, of: t, t_local_ms}` to `cs/<enc(b)>.reverts.jsonl`, print `REVERT_REPORT`.

## 4. How it uses existing mechanisms

- **Data source:** the live first-parent chain (reachable from `refs/cowork-remote/*`, survives saves and `gc --prune=now`, as `/cowork log`), indexed by the existing provenance journal (`cs_ids[]` per commit) and decoded with the existing `Cowork-CS`/`Cowork-CS-Paths` trailers. No board read beyond the fold the daemon already has.
- **Write:** the two-phase verifying writer's `writeLocalGroup` with `expectedCleanBlob`, exactly as `review <id> --accept` (SEC-33). Allowed only without FREEZE (glossary §8; stricter than §8, which still allows a human `/cowork resolve` while frozen).
- **Change-set:** one human-class CS, like HLD-36's `recovered` CS (a second human-class id beside an open human CS whose paths are disjoint because of `BUSY`). It publishes under S1's human close and joins publication groups by HLD-38.
- **Gates, unchanged except one attribution:** B1 (a hunk inside a foreign claim → whole-CS K6 PIN, local human + holder notice; claims of this PC's own seats are not foreign to a human hunk, REG-19), T0 (a teammate's later caller of a removed name → K7 PIN guard `t0`; its shrink guard counts the confirmed revert write as attribution, like a human save seen in 2 stable snapshots, HLD-50 item 3 edit), governor slot, MASK, S2 (a teammate landing the same lines between write and push → K4: TIP on disk, the revert version a PATCH record restorable with one command).
- **Revert detector:** the write is an *observed* delta (HLD-26, like a resolve write), so D2 does not re-test it and HLD-30's mass-change breaker does not count it (a 40-file revert never trips `MASS`); the same protection is applied earlier, at compute time, by step 5.
- **Seats, IPC, status.json:** the CLI asks the daemon over the existing IPC; the CS appears in `status.json.pending.cs_ready` until published. No new status field.
- **Visualizer:** a revert is one ordinary `publish` scene event of a human CS (12 §3.4 mapping table, one `Cowork-CS` trailer); teammates' viewers cannot tell it is a revert, by design (no protocol change).

## 5. Privacy and safety

- Nothing new leaves the PC: no op, no trailer key, no note. Teammates see an ordinary human CS by this user. "revert of" lives only in `cs/<enc(b)>.reverts.jsonl` (user-only ACL like the rest of `<gitdir>/cowork/`; display only; losing it loses only the label).
- The undo view and preview show only content already in the live chain or on this disk; rendered diffs are never written to the board, logs, `status.json` or any file (10-product §3.8 item 2). Filtered paths: stored form only, never smudged (DAT-20); binary paths: oids and sizes only; non-LIVE and `local_only` paths: path and reason only. Logs carry codes, counts and oids only.
- Never touched: a teammate's CS (refused), a teammate's later line (steps 4c and 5), quarantined or save-only paths (never in live commits; `NOT_LIVE`), held bytes (`BUSY`). No conflict marker is ever written. The verb is human-only (SEC-25); no MCP tool writes (SEC-27 unchanged); Claude's path is an ordinary Edit.

## 6. Requirements

- **FEAT-F10-01** `/cowork revert <cs_id>|last` MUST be an acting verb under SEC-25 with preview/confirm (LIF-02); `undo` MUST stay `RF_UNKNOWN_VERB`.
- **FEAT-F10-02** Only a CS whose every commit is on TIP's first-parent chain, written by this `peer_id` in one epoch and listed in the provenance journal MAY be reverted; others MUST be refused with the §2.5 codes. A `cs_id` MUST be resolved within one `(peer_id, epoch)` (HLD-33); an unqualified id found under two epochs MUST be refused with `AMBIGUOUS_ID`.
- **FEAT-F10-03** The computation MUST be Algorithm REV: per path, newest commit first, `merge-file` with ours = current, base = after, theirs = before; conflicting regions MUST keep the current text and be listed as kept hunks.
- **FEAT-F10-04** A path covered in any of the CS's commits by another CS MUST be skipped as `MIXED`; a CS without `Cowork-CS-Paths` MUST be treated as covering every path of its commit. The two sides of a rename in one of the CS's commits MUST be reverted together or skipped together (`RENAME_PAIR`).
- **FEAT-F10-05** In verb mode a path with local unshared or held changes, pending incoming change or disk ≠ team version MUST be skipped as `BUSY`.
- **FEAT-F10-06** A path whose result would remove or re-add a non-trivial line outside the CS's own journaled add/del sets that the journal attributes to another writer MUST be skipped whole (`TEAMMATE_LINE`).
- **FEAT-F10-07** The preview MUST list every changed path, kept hunk and skipped path with its reason, and SHOULD show the B1 and edit-check predictions.
- **FEAT-F10-08** The confirmed write MUST be one all-or-none `writeLocalGroup` with the digested disk blobs as expected values; any other writer outcome MUST write nothing.
- **FEAT-F10-09** The written paths MUST form one new human-class CS that is closed at once, is an observed delta (HLD-26), and passes B1, T0, MASK and the governor like any human CS; T0's shrink guard MUST count the confirmed revert write as attribution (HLD-50 item 3), so a shrink or deletion the human confirmed is not a K7 by itself.
- **FEAT-F10-10** `cowork_show(cs_id)` for a CS of this peer MUST append the undo view within 8,000 chars, diffing only in-file text changes and naming every other path with `T-SHOW_UNDO.human`; for another peer's CS it MUST NOT show one.
- **FEAT-F10-11** No board op, op field, trailer key, ref or remote-visible byte MAY be added; "revert of" MUST stay local.
- **FEAT-F10-12** RULES MUST stay unchanged (en and ko). The `cowork_show` tool description MUST say that a change-set id of this PC adds an undo diff, inside the CCI-47 ≤ 3,000-char schema total (measured together with F05's clause); `T-WAKE_RECAP` MUST carry one `T-WAKE_RECAP.undo` line naming `/cowork revert <id>` when ≥ 1 listed wake change-set is shared; `/cowork log` SHOULD show the revert hint and the local "revert of" label.
- **FEAT-F10-13** `last` MUST resolve to the newest closed CS of this peer and MUST refuse (`RF_REVERT_NOT_SHARED`), never skip to an older CS, while that CS is not fully shared.
- **FEAT-F10-14** In slash mode the preview MUST keep its headline and confirm line and cut lists in the §2.3 order; the preview id MUST digest the full lists.

## 7. Tests (SIM unless marked; virtual clock)

- **TC-F10-01 Basic.** A's seat CS `s1/4` adds `f()` (a.ts 10–20); B then adds line 5 and `g()` at the end of a.ts. `/cowork revert s1/4` → preview: a.ts −11, 0 kept; confirm → a.ts = TIP minus `f()`, B's line 5 and `g()` byte-equal; one live commit with one `Cowork-CS: <A>/human/<n> … origin=human`; no `revert` record, no `MASS`; B converges. INV-HLD-NOREVERT holds.
- **TC-F10-02 Kept hunk.** `s1/4` changed `x = 1` → `x = 2` (line 12) and added line 30; B later set line 12 to `x = 3` → line 30 removed, line 12 stays `x = 3`, preview lists "a.ts lines 12-12 stay: changed later by B".
- **TC-F10-03 Checkpoints.** One CS published as `checkpoint seq=1`, `checkpoint seq=2`, `closed seq=3`, each extending one function; a B commit between 1 and 2 edits another function → result = file before seq 1 plus B's edit, byte-equal.
- **TC-F10-04 Mixed.** One live commit carries `s1/4` (b.ts, c.ts) and `<A>/human/7` (b.ts) → b.ts `MIXED` naming `<A>/human/7`, c.ts reverted. Variant: `s1/4` has 300 paths (no paths trailer) and shares its commit with a CS listing b.ts → b.ts `MIXED`, the other 299 reverted.
- **TC-F10-05 Not own, undo, too old, epochs.** `revert <B's cs>` → `RF_REVERT_NOT_OWN`, exit 1; `/cowork undo x` → `RF_UNKNOWN_VERB`; a CS at +15 days → `RF_REVERT_TOO_OLD`, at +13 days → preview. A lost state restarts A's human counter in a new epoch, so `<A>/human/3` exists in both epochs inside the window → `AMBIGUOUS_ID` listing `<A>/human/3@<e1>` and `@<e2>`; each qualified form previews only its own epoch's commits.

## 10. Rejected alternatives

- Keeping each published `(A_cap, R)` for 14 days: it is the pre-merge capture, so it can differ from what landed (concat, rebase) and cannot separate same-path CSs either; the live commits plus the existing journal give the landed change with no new store.
