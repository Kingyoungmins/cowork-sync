# F05 — Claims ahead: who is changing what, seen before the edit

**Status:** proposal (spec delta against glossary rev 2.4). **Owner chapters:** 06-claude (carrier, handler), 07-coordination (templates, RULES), 10-product (human path view). **Protocol change:** none (`proto = 1` unchanged; no new op, field, ref, file or IPC frame). **Keywords:** RFC 2119.

## 1. Purpose

Today a Claude session learns *where* a teammate's session is changing code only when its own Edit is denied (K1, glossary §10), or when a teammate's change lands in a file it has read (`T-ATTRIB`, 06 §3.13 item 1); the digest gives only counts of other seats' claims (07 §3.17 item 4). By then it has usually planned and written the change. F05 shows the same fact earlier, from the **claim view** (glossary §3) this daemon already holds, in two ways: a **push** note when the session Reads a file containing a teammate's claim, and a **pull** answer when it asks `cowork_show` about paths. Claude can then order its work so the held parts come last. The K1 gate (glossary §11) still decides at edit time; F05 decides nothing.

F05 is **not** the "soft claim" that 07-coordination §1.2 refuses: it creates no claim, no reservation and no record, and nobody is told that someone read their code.

## 2. User-visible behaviour

### 2.1 Push: the claim-ahead note (`CLAIM_AHEAD`)

At PostToolUse(Read) of a **LIVE** path p by seat S (agent `a`, `main` for the top level), with a non-empty, non-ENOENT result:

1. **Read range** `RR`: `[offset, offset + limit − 1]` from the hook payload `read{offset, limit, full}` (06-claude §3.4); without `offset`/`limit`, the rows the host returned (its default line limit, pinned with the payload schema). Rows are disk rows, which equal stored rows (04-regions §3.2 item 5).
2. **Candidates**: every claim in S's claim view on p whose holder seat ≠ S (any `agent_id`), that is **not STALE**, and on which S holds no active go-first grant. This is: HELD folded claims of other seats of any peer, and **all** confirmed TENTATIVE claims of sibling seats on this peer (glossary §3 claim view). The K1 qualifier "earlier in local order" orders two claimants; a reader has no claim of its own in the comparison, and CLAIM step 5 (04 §3.5) already keeps local drafts from overlapping, so it does not apply here. Unconfirmed TENTATIVE claims are never listed.
3. **Overlap**: map the claim's ranges from its anchor blob (a sibling's unpublished claim: its draft `srcBlob`) to S's **view blob** of p (06-claude §2, set by this Read) with `mapRanges(…, mode: local)` (04-regions §3.4); when the view blob equals the anchor blob the ranges are used as they are, with no mapping. Overlap = closed-interval intersection with `RR`. `granularity: file` and a `WHOLE_FILE` result overlap every read; `TOMBSTONE` never overlaps.
4. **Notice key** `(seat, agent_id, claim_id)`. A key already in the context's *noticed set* produces nothing: re-reading the file stays silent while that claim stays in the claim view. The key deliberately has **no `anchor`**: a claim is re-anchored at every holder push that touches the path (04 §3.5 "Re-anchor (a)"), which under rev 2.4 edit checkpoints means every 10–30 s while the holder works, so an anchor in the key would re-note on almost every re-read. `claim_id` is stable across re-anchors (glossary §3); a new function is a new `claim_id`. A key is removed when its claim leaves the claim view (§2.2), whether or not the ended line is delivered, so a later re-claim of the same `claim_id` is noted again. The noticed set lives in daemon memory per (seat, agent); it is cleared at SessionStart `compact|clear|resume|fork` (the context lost the note) and at SubagentStart/SubagentStop for that agent.
5. **Render** one `CLAIM_AHEAD` note (template `T-AHEAD`, §2.5) in the PostToolUse **attribution slot** (600 chars in total, glossary §19). The slot carries `T-ATTRIB` first and `T-AHEAD` after it only when both fit in the 600 chars together; at worst-case placeholders they never do (`T-ATTRIB` 361 + `T-AHEAD` with 1 item 444, en), so in practice a due `T-ATTRIB` usually pushes the note to the next PostToolUse. A claim named in a **held-variant** `T-ATTRIB` ("that session still holds the function") carried in the same reply or already DELIVERED to this context is not listed again: its key enters the noticed set with that batch. Items are ordered by first row; at most **3** items, and fewer when the next item would pass the slot cap; the rest become `T-AHEAD.more` "and k more: cowork_show({file})" (07 §3.14 overflow form, pointing to `cowork_show` because `cowork_status` does not list teammates' claims). If not even one item plus the overflow clause fits, the note waits for S's next PostToolUse in the same turn; a note still undelivered at that turn's Stop is dropped and its keys are **not** marked noticed.
6. Keys enter the noticed set only when the batch carrying them is DELIVERED (`printed{batch_id}`, 07 COO-20).

Example (en, 278 chars): `cowork-sync status, not a lock: in billing/tax.ts, other sessions are changing computeTax (lines 40-88, Minji's session). That code is their unfinished work; other parts can go first. An edit there is checked when made, and a stopped one is kept as a request for cowork_request.`

### 2.2 The ended line (`CLAIM_AHEAD_ENDED`)

When a claim whose key is in a context's noticed set leaves the claim view, that context gets one `T-AHEAD.ended` line at its next carrier (PostToolUse attribution slot, else the next UserPromptSubmit digest delta), and the key is removed at once (§2.1 step 4). A context that was never told gets nothing. A re-anchor of a still-active claim produces no ended line. The cause selects `{AHEADEND}` (§2.5) from the fold's record of the claim (02-protocol §3.3 release reasons):

| Claim left the view by | `{AHEADEND}` |
|---|---|
| `release` with reason `explicit`, `answer`, `stop` or `reservation_transfer` | #1 released |
| `release` with reason `save` | #2 saved |
| `seat_end` (op, or `release{reason: seat_end}`), `leave`, or the fold-derived `superseded` (a new-epoch `join` retired the holder's epoch) | #3 that session ended |
| an applied `presume_absent` on the holder's epoch (STALE) | #4 did not answer a teammate's request for 30 min |

`presume_absent` exists only for a holder PC with an open request or a grant from the writer (PRO-35, INV-PRO-LIVE); it is not a general inactivity timer, so #4 says so. A context that is itself the requester and gets a `T5.*` result (for example `T5.free.head`) naming the same claim gets no ended line for it: the same fact is not told twice.

### 2.3 Pull: `cowork_show(id)` takes paths (argument extension, no new tool)

`id` becomes `string | string[]` (array ≤ 20). Each string is resolved by the 10-product §3.8 dispatch order (ids first), then as a repo-relative path, then — if it contains `*`, `?` or `[` — as a glob in the 03-data §3.6 dialect over the tracked and admitted paths of TIP and the worktree. A string matching nothing is `UNKNOWN_ID` (as today). Matched paths are de-duplicated and sorted; beyond **20**, the first 20 are shown plus `R.show.more`. When the rows of the shown paths would pass 8,000 chars (20 paths with several claims each easily can), whole paths are dropped from the end and counted in the same `R.show.more` line; only when the first path alone passes the cap (about 35 claims in one file) are its rows cut after the last one that fits, and the 06 §3.16.2 count line names the claims left out.

Result (≤ 8,000 chars, glossary §19; `R.show.*` templates): one header `R.show.head` (fold age, "status only, not a lock"); per path either `{path}:` followed by one `R.show.row` per overlapping teammate claim — `{label}`, lines, holder actor phrase, `{ACT}`, local age, open-request count — or `R.show.free` ("free") or `R.show.notlive` (scope class, no claims possible). `{ACT}`: a sibling seat shows its local activity (`working now` = MID_TURN, `waiting for its user` = AWAITING_PERMISSION, `idle` = IDLE); a seat on another peer shows `last board activity {dur} ago` (local Δmono since this daemon folded that (peer, epoch)'s newest board commit) or `away` (ghost, glossary §3). Remote turn activity is not on the board, and F05 does not add it. "Local age" = Δmono since this daemon first folded the `claim_id`. **Lower-bound rule:** both durations are measured from a local fold, not from the teammate's action (INV-CLOCK). When that fold happened during this daemon's start-up catch-up or in the first fetch after an `OFFLINE` episode, the true age can be hours longer, so the duration renders as a lower bound: `≥ {dur}` (ko `{dur} 이상`). Without this rule a 3-hour-old commit replayed at start-up would read "last board activity 1 min ago". "Open requests" = non-terminal requests whose `claim_ids` contain it. Teammate notes are not shown here (they stay in `cowork_show(<rid>)`).

**Polling guard:** for the same (seat, sorted matched path set), a second call within **30 s** of the last full result whose claim-view digest over those paths is unchanged returns `SHOW_NO_CHANGE` (`R.show.throttle`), as `cowork_status` does (06 §3.16.3). A changed digest returns the full result.

### 2.4 Human: `/cowork show <path|glob>`

The 10-product §3.8 path view keeps its scope line and adds a **Teammates' claims** section with the same rows (`UI_PATH_CLAIMS_HEAD`, `UI_PATH_CLAIM_ROW`, `UI_PATH_NO_CLAIMS`, activity labels `UI_ACT_WORKING`, `UI_ACT_WAITING_USER`, `UI_ACT_IDLE`, `UI_ACT_LAST_BOARD`, `UI_ACT_AWAY`), in all six languages, slash-mode output ≤ 4,000 chars. A glob shows ≤ 20 paths. `--json` adds `data.claims[] = {path, claim_id, label, ranges, holder_display, activity, age_s, open_requests}`.

**Globs through the `!` line.** `commands/cowork.md` runs `node … cli.js $ARGUMENTS` unquoted (10-product §3.3). Where the `!` line runs in bash or sh, an unquoted `billing/**/*.ts` is expanded by the shell into several paths before the CLI sees it (and `**` acts like `*` without `globstar`); in PowerShell it arrives as one literal glob. So `show` MUST accept one or more positional path/glob arguments and treat several as the list form (resolved one by one as in §2.3, de-duplicated, ≤ 20 shown plus `UI_AND_MORE`); the README `show` line tells humans to quote a glob (`/cowork show "billing/**/*.ts"`) so every shell gives the same result. With two or more arguments each one is resolved as a path or glob only (ids are shown one per call, as today), so a shell-expanded file name that happens to look like an id is still shown as a path.

## 3. How it uses existing mechanisms

- **Claim view and fold** (glossary §3, §7; 02-protocol fold; 04-regions REG-23): read only. The same view the K1 gate uses, so a note and a later deny never disagree about who holds what at that fold.
- **Hooks and carriers** (06-claude §3.4, §3.14): the existing PostToolUse `.*` registration, its reply, `batch_id`/`printed` confirmation and the attribution slot. No new hook, matcher or carrier row. Precedent: `HOLD_IN_FILE` already lists hold records at PostToolUse(Read) (06 §3.13 item 2), in the 1,000-char coordination-event slot; F05 uses the 600-char attribution slot, so the two never compete for space.
- **Seats** (06 §3.11): per-seat budget meter and `PULL_MODE` (§3.16.1), seat activity, actor phrases (07 §2).
- **MCP** (06 §3.16): the existing `cowork_show` tool and the existing MCP↔daemon request path; only its argument schema grows. Still eight tools (glossary §15).
- **CLI** (10-product §3.8): the existing path branch of `/cowork show`.
- **Board ops, holds, status.json, IPC frames, the visualizer's event model:** unchanged. Reads are not board facts, so 12-visualizer gets no scene event (INV-VIZ-NOCONTENT and its read set are untouched).
- No server, no relay, no telemetry, no new transport, no new file on disk.

## 4. Privacy and safety

1. **Nothing leaves the PC.** Which files a seat reads, its read ranges and its noticed sets are never written to the board, a ref, `status.json`, an event or a doorbell; the holder is never told that its code was read. Daemon logs record only codes and `claim_id`s (09-security log rules).
2. **Only board facts already folded on this PC are shown**: label, line numbers in the reader's own view, holder display name, board-derived activity and counts. Never code bytes, diffs, hold blobs, teammate note text (only `cowork_show(<rid>)` shows notes, in `T-NOTE`), another seat's read set, or remote turn state.
3. Non-LIVE paths (QUARANTINED, SAVE_ONLY, UNMANAGED, NOT_ADMITTED, LOCAL_ONLY) never carry claims and get no note; the path view shows only their scope line.
4. **Not a lock, not a permission.** The two texts that present held claims (`T-AHEAD`, and `R.show.head` above every path-view row) say "not a lock" / "잠금 아님" (FEAT-F05-14); no F05 text uses an imperative to Claude (07 §3.16 voice), or the words lock/locked/permission/allowed/reserved outside "not a lock"/"잠금 아님". A missing note never means "free to edit": the K1 gate and B1 stay the only decisions (glossary §11).
5. Board-sourced strings pass `sanitize(…, "claude")` (SEC-34) and REG-34 label verification before rendering.

## 5. Requirements

- **FEAT-F05-01** At PostToolUse(Read) of a LIVE path, the daemon MUST compute claims ahead exactly as §2.1 steps 1–3 (claim view of the reading seat, holder seat ≠ reader, no STALE, no claim the reader holds a grant on, `mapRanges` local to the view blob, closed intersection with the read range) and MUST NOT list unconfirmed TENTATIVE claims.
- **FEAT-F05-02** The note MUST be one `CLAIM_AHEAD` in the PostToolUse attribution slot (≤ 600 chars in total, after `T-ATTRIB` when both fit), with ≤ 3 items and the `T-AHEAD.more` overflow clause, waiting for the next PostToolUse of the same turn when it does not fit and dropped (keys not marked) at that turn's Stop. A claim named in a held-variant `T-ATTRIB` in the same reply or already DELIVERED to the context MUST NOT be listed again.
- **FEAT-F05-03** The daemon MUST emit at most one note per notice key `(seat, agent_id, claim_id)` while that claim stays in the claim view (a re-anchor MUST NOT re-note), MUST mark keys only on DELIVERED batches, MUST remove a key when its claim leaves the claim view, and MUST clear a context's noticed set at SessionStart `compact|clear|resume|fork` and at SubagentStart/SubagentStop of that agent.
- **FEAT-F05-04** `CLAIM_AHEAD_ENDED` MUST be emitted at most once per noticed key whose claim leaves the claim view, with `{AHEADEND}` chosen by the §2.2 table, and never for a key the context was not told about or for a re-anchor.
- **FEAT-F05-05** Both codes MUST be suppressed under `PULL_MODE` (non-mandatory, like `ATTRIBUTION`), MUST count toward the CCI-46 injected-chars meter, and MUST stop for the rest of the seat-hour once they used 5,000 chars.
- **FEAT-F05-06** Computing a note MUST NOT delay the Read's hook reply beyond 5 ms of daemon main-thread work; mapping MUST run in the worker pool, and a late result MUST ride the next PostToolUse.
- **FEAT-F05-07** F05 MUST NOT write any board op, ref, hold record, `status.json` field, log text beyond codes and `claim_id`s, or doorbell, and MUST NOT change any gate (G1–G4) or B1 verdict.
- **FEAT-F05-08** `cowork_show` MUST accept a string or an array of ≤ 20 strings, each resolved as id → path → glob (03-data §3.6 dialect), and MUST render the §2.3 path view within 8,000 chars, showing ≤ 20 paths plus `R.show.more` and dropping whole paths from the end beyond the cap.
- **FEAT-F05-09** Remote holder activity MUST be derived only from folded board facts (`last board activity {dur} ago` or `away`); sibling seats MUST show their local activity; a duration measured from a fold made during start-up catch-up or the first fetch after an `OFFLINE` episode MUST render as a lower bound (`≥ {dur}` / `{dur} 이상`).
- **FEAT-F05-10** A repeat path-view call for the same (seat, path set) within 30 s with an unchanged claim-view digest MUST return `SHOW_NO_CHANGE`.
- **FEAT-F05-11** The MCP tool set MUST stay the eight glossary §15 tools and the schema total MUST stay ≤ 3,000 chars (CCI-47).
- **FEAT-F05-12** `/cowork show <path|glob>…` MUST add the §2.4 claims section in all six human languages, within the slash-mode 4,000-char cap, and MUST accept several positional path/glob arguments (a shell-expanded glob) as the list form.
- **FEAT-F05-13** The `cowork_show` tool description MUST carry the §2.6 path clause, and RULES MUST stay unchanged unless the §2.6 alternative is adopted after a failed T-F05-reorder (then ≤ 1,000 chars in en and ko, re-measured on the RULES text current at that time).
- **FEAT-F05-14** The two texts that present held claims, `T-AHEAD` and `R.show.head` (every `R.show.row`/`.free`/`.notlive`/`.more` appears only under `R.show.head`), MUST state "not a lock"/"잠금 아님"; no F05 template MAY contain an imperative addressed to Claude, or lock/locked/permission/allowed/reserved (en) or 잠김/허가/허용 (ko) outside that phrase.

## 9. Deviations from the story, and open questions

1. **Overflow pointer** is `cowork_show({file})`, not `cowork_status`: `cowork_status` lists only the seat's own claims (06 §3.16.3).
2. **Remote "MID_TURN/IDLE"** cannot be shown without a protocol change (seat activity is not on the board); F05 shows `last board activity {dur} ago` / `away` for remote holders and exact activity only for sibling seats. Default: as specified; publishing activity is a protocol v2 candidate.
3. **Dedupe key** adds `agent_id`, because a subagent has its own context, and (after review) leaves out `anchor`, because anchors change at every holder push.
4. **Polling guard** returns the full result inside 30 s when the claims changed (same rule as `cowork_status`); the story said "once per 30 s". Default: as specified (an unchanged answer is the only waste).
5. **RULES** (changed in review): default is RULES unchanged and the hint in the `cowork_show` tool description (§2.6); the trimmed RULES line is the alternative if T-F05-reorder fails.
6. The 5,000-char sub-budget is a new number (not in the story) so that claim-ahead notes alone can never push a seat into `PULL_MODE`.

## Review notes

Adversarial review, 2026-10-08, against glossary rev 2.4, chapters 00–12, the roadmap, the Plan 2 contract and the other proposals in `docs/proposals/`. Template and RULES lengths were re-measured by script at the 07 §3.16.3 worst-case placeholders. The original figures were exact (RULES 997 / 589; `T-AHEAD` 444 / 337, 553 / 440, 587 / 460; `R.show.head` 124 / 68). `R.show.row` came out 3 chars longer than stated.

**Not already in the spec.** The closest existing pieces are `HOLD_IN_FILE` (hold records, not claims), `T-ATTRIB` (only after an apply lands in a read file), the 07 §3.17 digest (only *counts* of other seats' claims), `T4` (conflicts only), `cowork_status` (own claims only), `cowork_show(<claim_id>)` (needs an id Claude does not have), `/cowork status` (teammates' claim counts per holder) and the `/cowork show <path>` path view (scope line only). The 07 §1.2 "soft claims" refusal is correctly disclaimed: nothing is reserved or recorded. No invariant breaks: no board op, ref, `status.json` field, doorbell or telemetry; no change to G1–G4, B1, holds or MASK; non-LIVE paths carry no claims; the holder is never told its code was read.

**Changed in this review**
1. **Dedupe key** `(seat, agent_id, claim_id, anchor)` → `(seat, agent_id, claim_id)`. Every holder push that touches the path re-anchors the claim (04 §3.5 "Re-anchor (a)"). Under rev 2.4 edit checkpoints that happens every 10–30 s, so the old key re-noted on almost every re-read of a file an active teammate is editing. Keys are now removed when the claim leaves the view, even if the ended line is suppressed. T-F05-dedupe and FEAT-F05-03 were inverted to match.
2. **"Earlier in local order"** was dropped from the sibling-candidate rule (§2.1 step 2). The phrase orders two K1 claimants, and a reader has no claim in the comparison.
3. **`{AHEADEND}` #3 was wrong about the protocol.** `presume_absent` fires only for a PC with an open request or a grant (PRO-35, INV-PRO-LIVE), never after general inactivity. It is now #4, with the facts of 07 `{FREEREASON}` #3. The §2.2 causes `superseded`, `leave` and release reason `save` had no value; a full mapping table and a `saved` value were added. `T-AHEAD.ended` was re-measured at 332 / 273, within 600. A requester that gets a `T5.*` result about the same claim no longer gets the ended line as well.
4. **Attribution-slot arithmetic.** At worst case, `T-ATTRIB` (361) plus `T-AHEAD` (444 minimum) exceeds 600, so they share the slot only at realistic lengths. This is now stated, and the 06 §3.14.1 / glossary §19 edit text says "slot of 600 in total, `ATTRIBUTION` first", not "one note". A claim already named by a held-variant `T-ATTRIB` is no longer listed twice. At worst case the en note carries 2 items, not 3.
5. **RULES default flipped.** RULES stays unchanged, and the pull hint goes in the `cowork_show` tool description. Three reasons: proposal F10 also rewrites RULES (to 995 of 1,000), so the two trims cannot both merge; the trims dropped "other work continues" and "to this user" from the one always-on text; and the push note already teaches `cowork_show({file})`. The trimmed line remains only as an alternative after a failed T-F05-reorder. FEAT-F05-13, T-F05-text, §7 and §9 item 5 were updated to match.
6. **Rule-id collision.** F10 also claims CCI-57. §7 now says "next free CCI/COO/UX numbers at merge" and "next free change-log §".
7. **Globs through the `!` line.** `$ARGUMENTS` is unquoted (10-product §3.3), so bash and sh expand `billing/*.ts` into several arguments while PowerShell does not. `show` now accepts several positional paths as the list form, the README tells humans to quote globs, and T-F05-cli covers both shells.
8. **Remote activity after a catch-up.** The `{dur}` in "last board activity" and in "held" is measured from this daemon's fold. After a daemon restart or an offline reconnect, a 3-hour-old commit would read "1 min ago". Such durations now render as lower bounds (`≥ {dur}` / `{dur} 이상`; FEAT-F05-09, T-F05-show).
9. **Path view over 8,000 chars.** No overflow rule existed (20 paths × several claims each overruns the cap). Whole paths are now dropped from the end and counted in `R.show.more`.
10. **`R.show.head` ko** lacked the literal "잠금 아님" that FEAT-F05-14 requires, and now contains it. §4 item 4 now matches FEAT-F05-14: only the two claim-presenting texts must say "not a lock".
11. **Real-Claude budget.** T-F05-reorder no longer reserves 10 nightly runs. It runs in the TST-19 weekly rotation, inside the shared ≤ 30 runs per night (FEAT-F05-15 updated).
12. **Plan 6 cost soak.** The soak must run with claim-ahead notes on (§8, §7 11-testing). §7 also gains the missing 07 §3.17 digest line for `T-AHEAD.ended`.
13. Small fixes: Purpose no longer claims that a deny is the only signal today (it now names `T-ATTRIB` and digest counts). §2.1 step 3 adds an identity fast path when the view blob equals the anchor blob. §3 names `HOLD_IN_FILE` as the precedent.

**Placement and "implementable now"**: confirmed. Plan 2 folds `claim` ops as no-ops (contract R-12), and no hook carrier, seat or MCP server exists yet. F05 needs Plans 4, 5 and 6 (Plan 3 indirectly), with the human view in Plan 7. Implementable now: **no**. It needs no protocol change, so it can also land after the public release.
