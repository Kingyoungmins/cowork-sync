# F12 — End-of-day wrap and save-summary draft (`/cowork wrap`)

**Status:** proposal (spec delta) against glossary REVISION 2.4 and chapters 01–12 · **Protocol change:** none (no board op, no trailer, no `status.json` field, no new transport; can ship after the public release) · **Owner chapters:** 10-product (the screen), 08-lifecycle (the shared attribution function and the save preview) · **Touches:** 00, 04, 05, 06, 07, 09, 11 (wording only) · **Shares with F14:** the in-memory latest edit-check result (`last_check`, F14 §4) and its silence-rule amendments (F14 §8 items 1b, 5–7) · **Visualizer (12):** no change

## 1. Purpose

At the end of a day a developer wants one screen that answers: what of mine is not shared yet, who is waiting for my decision or on my claims, and whose team work is still unsaved — and then to pick save, hand off, step away or stop. Today that takes `status`, `queue` and a dry `stop`. And `/cowork save "<summary>"` starts from an empty summary even though the daemon already computes, for the save trailers, exactly who changed which region since the last save (08 §3.7.2, LIF-27).

F12 adds (a) the read-only verb `/cowork wrap`, which collects existing state into one capped screen and ends with the commands the human may type, and (b) a deterministic **summary draft** rendered from the §3.7.2 attribution table, shown in `wrap` and in the `save` preview, never used without the human typing it.

## 2. User-visible behaviour

### 2.1 `/cowork wrap [--json]`

Read-only (glossary §15 class). No human evidence, no preview/confirm, no human-lease renewal, no fetch or push, no board op. It works from a terminal like every verb. Inputs: `status.json` read directly for the headline (as `status`, 10 §3.5), then one authenticated IPC request for the detail (as `status`). If IPC fails it prints the headline, `UI_DETAIL_UNAVAILABLE`, the headline's own next line and exits 0.

Sections, printed in this order (a section with no items prints nothing, as UX-07):

| # | Section (header code) | Content and source | Cap (tty / slash) |
|---|---|---|---|
| W1 | headline | the 10 §3.5 headline row, its next line, and every line `status` prints directly under it: `UI_ALSO_PAUSED_BY`, `UI_FROZEN_STILL_WORKS` / `UI_FROZEN_NO_PUSH` when frozen, `UI_PUSH_SLOWED` / `UI_PUSH_SLOWED_TEAM` during the throttle fallback | always |
| W2 | Needs you (`UI_SECTION_NEEDS_YOU`) | the items of `status` section 2 (UX-07, same rule and same `UI_HOLD_REASON_<KEY>`), plus incoming requests on this PC's claims with `UI_HOLDER_ASKS_YOU` and `UI_HAS_NOTE` (never note text); each line ends with the action `status`/`queue` already prints for it: the first action of the 10 §3.7 queue table when the item is a request or record with a row there, otherwise the item's own `NX_` next line (blocked adopt, `not_converged`, invalid config, `BOARD_FULL`, `HOLD_MASK_INVALID`) | 10 lines + `UI_AND_MORE` |
| W3 | Not shared yet (`UI_SECTION_WRAP_UNSHARED`) | this peer's open seat CSs (`UI_WRAP_CS_OPEN`: seat label, file count, unpublished age in local Δmono, and the last edit-check result, §2.4), ready CSs not yet published (`UI_WRAP_CS_READY` with the headline's reason), the open human CS (`UI_WRAP_CS_HUMAN_OPEN`), and this peer's non-terminal PIN records with their `UI_HOLD_REASON_<KEY>` | 10 lines |
| W4 | Your claims (`UI_SECTION_WRAP_CLAIMS`) | `UI_WRAP_CLAIMS_TOTAL` "{c} claims; {n} teammates are waiting on {m} of them", then per claim of this peer: label, path, state, waiting count (§2.5), sorted by waiting count descending, then label, path | 10 lines |
| W5 | Team work not saved (`UI_SECTION_WRAP_UNSAVED`) | LIVE_UNSAVED (glossary §3) grouped by author (§2.8): `UI_WRAP_UNSAVED_BY` "{name}: {n} files" (`UI_WRAP_UNSAVED_YOU` for this peer), then `UI_WRAP_UNSAVED_EARLIER` "{n} files changed before the last save or branch move" for paths with no commit in the walked range, then the paths. Order: this peer first, then names by code point; **never by count** (the section is not a ranking). Every LIVE_UNSAVED path is counted somewhere | 6 authors, 20 paths |
| W6 | Undo candidates (`UI_SECTION_WRAP_REVERT`) | only when F10 is merged: F10's candidate predicate applied to this peer's `Cowork-CS` groups on `(G, TIP]`, i.e. **since the last save or branch move** (G = the base-move commit that introduced `live_base(TIP)`, which a human branch commit can also create, 08 §3.12; no wall clock is read, INV-CLOCK), newest first, with F10's own command per row | 5 lines |
| W7 | Summary draft (`UI_SECTION_WRAP_DRAFT`) | §2.2 | 12 bullets / 1,000 chars |
| W8 | Commands (`UI_SECTION_WRAP_COMMANDS`) | §2.3 | always |

**Slash cap** (glossary §19: 4,000 incl. frame lines; UX-03). W1 and W8 are reserved first (W8 ≤ 900 chars at worst-case params in all six languages). The remaining space is filled in priority W2, W3, W4, W5, W6, W7; the first section that does not fit is cut at a line boundary with `UI_AND_MORE`, later ones are dropped, and `UI_TRUNCATED_SLASH` (with the absolute terminal `… cli.js wrap` command) is printed **directly above** W8, so the commands are never cut. UX-03 today says slash output ends with `UI_TRUNCATED_SLASH`; §7 amends it for a verb whose output ends with a commands block. A typical wrap (≤ 3 open CSs, ≤ 5 claims, ≤ 20 unsaved paths) SHOULD stay ≤ 2,500 chars because slash output may count toward the 20,000 chars per seat-hour budget (10 §8 Q2).

### 2.2 The summary draft

One function, `saveAttribution(G, L, Hb)`, is the §3.7.2 computation lifted out of save: for each live commit c on the first-parent chain `(G, L]`, the author name of c and REG-'s mapper over `diff(c^1, c)` at c, keeping only paths in `diff(Hb, L)`; result: the table `{path, label, displays[]}` that §3.7.2 turns into `Cowork-Symbol` lines. Save trailers and the draft both call it; nothing else computes attribution. Chain end: in `wrap`, `L = TIP` (labelled `UI_DRAFT_AS_OF` "as of team version {oid8}; a save may include fewer changes; your {n} unshared change-sets are not in it"); in the `save` preview, `L = Lk`, so the draft and the commit's `Cowork-Symbol` trailers describe the same set. A path with no grammar (unsupported language, or before Plan 4) maps to its whole-file region, as 04-regions already does, so the draft is defined on every repo. Budget: the §3.7.2 10 s of wall time, waits included; over it → `UI_DRAFT_UNAVAILABLE` and the rest of the screen or preview is unchanged. Per-commit mapper results SHOULD be memoized by commit oid for the daemon's life (LRU, ≤ 5,000 entries), **except** a result in which any path's table was `NO_TABLE{budget}` or any mapping fell back to WHOLE_FILE because a time budget fired (REG-31, glossary §20 "Region mapper", "Parse"): such a result is used once and not memoized, so a later call can map the path properly.

**Worker priority.** The mapper runs in the REG worker pool (REG-31), which the gate, CONFIRM, the edit check and T0 also use. `saveAttribution` takes a priority argument: the draft (in `wrap` and in the save preview) runs at **background** priority — the lowest in the pool, below the edit check (which already runs below gate parses and confirmations, 06 §3.16.1 "Cost impact of edit checkpoints" item 3), one commit per job, at most one worker at a time, so every gate, CONFIRM, edit-check and T0 job runs before any queued draft job — so a human looking at `wrap` never slows a live seat's edits or publishes. Save's own trailer computation keeps its current priority (with the memo it normally re-uses the preview's work).

**Determinism.** For equal inputs and **equal mapper results** the draft body is byte-identical on every PC with the same `L_h`. Mapper results can differ between PCs only where a time budget fired on one of them (a slower PC maps that path to its whole-file label); this is the same per-PC behaviour as every other REG decision and is not corrected here.

Rendering (catalog codes in `L_h`, one renderer, I18N-07):
- Label line `UI_DRAFT_LABEL`: "Suggested summary — DRAFT. It lists what changed, not why. Edit it before you save."
- Headline `UI_DRAFT_HEADLINE` "Changes in {zones}" / `UI_DRAFT_HEADLINE_MORE` "… and {n} more areas": the ≤ 3 areas with the most rows, ties by area key.
- One bullet per area, `UI_DRAFT_BULLET` "- {zone}: {labels} ({names})": labels sorted by (path, label), ≤ 4 then "+k"; names sorted by code point, ≤ 3 then "+k"; ≤ 100 rendered chars per bullet; bullets sorted by area key (code point). **Length rule** (deterministic): while a bullet is longer than 100 rendered chars, drop the last shown label into "+k", down to one label; then the last shown name into "+k", down to one name; then cut the zone, and last the one label, with a middle ellipsis until it fits.
- **Area** = `zone(p)` of 12 §3.5.3 (first two segments for a path of ≥ 3 segments, first segment for two), except that a root-level file is shown by its own name instead of `·`; the layout-only overflow zone `…` is never used.
- Nothing changed since the last save → `UI_DRAFT_EMPTY`.

Every placeholder passes `sanitize()` (SEC-34, `terminal` channel) and its type cap (names 20 rendered, label 80, path 80). The headline and each bullet then pass `scanSecrets` with `ctx.kind = commit_message` (SEC-08, the check save itself runs on the summary); a hit drops that bullet (a headline hit replaces the headline with `UI_DRAFT_HEADLINE_PLAIN` "Changes in several areas", which has no placeholder) and adds `UI_DRAFT_DROPPED` "{n} lines left out". The draft never contains a line starting with `Cowork-`, an e-mail address, a `peer_id`, note text, host text, file content or a date.

**Paste-safe.** The draft exists to be copied by the human into `/cowork save "<summary>"`, whose `!` line hands `$ARGUMENTS` to a shell (10 §3.3, 06 §3.2). `sanitize()` does not neutralise shell syntax, and display names (64 raw chars of free text) and labels are teammate-controlled, so a display name such as `$(touch pwned)` would run on the human's PC the moment they paste it. Therefore every draft placeholder gets one more pass after `sanitize()`: `"`, `` ` ``, `$`, `\` and `!` are replaced by their full-width forms (U+FF02, U+FF40, U+FF04, U+FF3C, U+FF01), and the catalog lint (I18N-07) fails on any `UI_DRAFT_*` template, in any of the six languages, that contains one of these five characters. A pasted draft line then contains nothing that a POSIX shell or PowerShell expands inside double quotes. The pass applies to the draft only (W7, the save preview, `--json` `data.draft`); other sections are never meant to be pasted and keep the plain `sanitize()` output.

### 2.3 Commands block (W8)

Header `UI_WRAP_RAN_NOTHING`: "wrap changed nothing and runs nothing. Type the command you choose; acting commands still preview and need your confirm." Then, each only when its condition holds, in this order:

| Line | Condition | Text (fixed command table; never board data except validated ids) |
|---|---|---|
| `UI_WRAP_CMD_SAVE` | LIVE_UNSAVED ≠ ∅ and none of the save refusals below is decided | `/cowork save "<your summary — start from the draft above>"`; followed by `UI_WRAP_SAVE_APPROVE_FIRST` "save will first ask you to approve the team's save check" when `checks.save` is set and its SHA-256 is not in `user.json.saveCheckApproved` (08 §3.7 step 0, `SAVE_CHECK_UNAPPROVED`) |
| `UI_WRAP_SAVE_BLOCKED` | LIVE_UNSAVED ≠ ∅ and an 08 §3.7 step-1 refusal is already decided by `status.json` or the IPC detail: `SAVE_FROZEN`, `SAVE_PUBLISH_PAUSED`, `SAVE_BASE_MOVE_BLOCKED` (ACTIVE base-move hold in the fold) or `SAVE_CONFIG_INVALID`, the first that applies in step-1 order | "save would be refused now [{code}]; see /cowork status" |
| `UI_WRAP_CMD_HANDOFF` | F08 merged and a claim of this peer has ≥ 1 waiting teammate | F08's form with that claim's `claim_id` (the claim with most waiters) and the literal placeholder `<teammate>`; the waiting names are shown after it as data, `UI_WRAP_WAITING_NAMES` |
| `UI_WRAP_CMD_AWAY` | F01 merged and (own claims or incoming requests) ≠ ∅ | F01's form with the literal placeholder `<time>` |
| `UI_WRAP_CMD_STOP` | repo live | `UI_WRAP_STOP_OPTIONAL` "Not needed to finish the day: closing a Claude session releases its claims, and cowork-sync goes idle by itself once no session is open. stop leaves live mode for this repo on this PC (all your claims released, held changes parked, other sessions here no longer coordinated); /cowork start brings you back." then `/cowork stop`, followed by `UI_WRAP_STOP_KEEPS` "stop keeps files; {n} files hold unsaved team work" when LIVE_UNSAVED ≠ ∅, or `UI_WRAP_STOP_WOULD_REFUSE` "[{code}]" when an 08 §3.9 step-0 refusal (or HLD-63's durability refusal) is already decided by `status.json` or the IPC detail: `STOP_GIT_OP` (E5), `STOP_INCIDENT`, `STOP_PUBLISH_PAUSED`, `STOP_SEAT_BUSY` (another local seat mid-turn now), `STOP_HOLDS_NOT_DURABLE` (a non-`local_only` record not yet durable, HLD-62) |

The draft is **never inside a command line**: 10 §3.2 renders `{cmd}` only from the fixed command table, and a board string inside a `$ARGUMENTS` line would be both a prompt-injection surface (slash output is read by Claude) and a shell-quoting hazard (`"`, `` ` ``, `$`, `\`, newlines). The human copies text from the W7 block into their own summary. If F01 or F08 is absent its line is omitted with no placeholder and no header residue.

### 2.4 Edit-check reason (W3)

There is **one** in-memory store of the latest edit-check result per open seat CS: F14's `last_check` (F14 §4: `{edit_n, kind: fail | incomplete | stale | skipped, check?, path?, line?, skip?, more}`, written by HLD-67 step 4, the T0-at-publish drop and 06 §3.8.4's skip conditions; cleared when the CS closes or a passing capture with a higher `edit_n` lands; never persisted, logged, published or delivered to a seat carrier; lost at daemon restart). F12 adds no second store. If F12 lands before F14, F12 introduces `last_check` with exactly F14 §4's shape and write/clear rules (only `kind: fail | incomplete` are needed by `wrap`; F14 later adds the rest), and F14 then reuses it.

Rendering in W3, one line per open seat CS that has a `last_check`:
- with F14 merged: F14's nested `{last}` codes (`UI_FLOW_LAST_*`) and `UI_FLOW_CHECK_LEGEND` once per output, so the same fact reads the same in `status --flow` and `wrap`;
- without F14: `UI_WRAP_EDITCHECK_PARSE` (check 1, "{path}: the last edit does not parse yet"), `_CALLERS` (2, "{path}: callers of a changed interface are not updated"), `_NAME` (3, "{path}: uses a name that is not defined"), `_SIZE` (4, "{path}: too many definitions or a large shrink"), `_SLOW` (`incomplete`, "{path}: the last edit could not be checked in time"), `_UNCHECKED` (a failure whose `editCheck` `reason` is `no_snapshot`, `merge_conflict` or `no_merge`, 04 §3.20: "{path}: the last edit could not be checked against the team version yet"). These reasons never render as checks 1–4.

The raw `reason` string, symbol names and file content are never shown (F14 §5). Nothing about the result is journaled, put in `status.json`, put on the board, or delivered to any seat carrier (06 §3.14.1), human mirror or OS notification; it reaches a screen only when a human types `wrap` (or, with F14, `status`/`show`).

### 2.5 Waiting teammates (W4)

`waiting(claim)` = the number of distinct `from.peer` over folded non-terminal `requests` (02 §3.3 fold state) whose `to_holder.peer` is this peer and whose `claim_ids` contain the claim. Nothing else counts: a K1 deny whose leftover is not yet offered is not visible to the holder as a request by design (U5, glossary §7 `request`), and K-kind events do not reach the board (12 §1.5 item 7).

### 2.6 Save preview

08 §3.7 step 6 gains one item after "check results": the draft for `(G, Lk]` under `UI_DRAFT_LABEL` (≤ 8 bullets in slash mode; dropped first when the preview exceeds the slash cap). It is not part of the preview id digest (LIF-02 digests the verb, normalized arguments, oids, paths and record ids; the draft is derived from those), so showing it never makes a confirm stale. Because 08 §2.1 defines the digested `items` as exactly the oids, paths and record ids the preview *printed*, and the draft prints root-level file names, §7 amends 08 §2.1 and LIF-02 to say that the draft's rendering is not a source of `items` (every path it names is already in the digested `diff(Hb, Lk)` list). If the typed summary, normalized (NFC, trimmed, whitespace collapsed), equals the draft's headline or the headline followed only by bullets of that draft, the preview adds the warning `UI_SAVE_SUMMARY_IS_DRAFT` ("This summary is the draft unchanged. Consider saying why."); it is a warning, never a refusal. The summary still changes the id (normalized arguments), so improving it means a fresh preview, as today. `SAVE_SUMMARY_EMPTY` keeps its condition and refusal; only its `next:` line becomes `NX_WRAP_THEN_SAVE`: "`/cowork wrap` shows a suggested summary; then `/cowork save "<summary>"`".

### 2.7 `--json`

Envelope `cowork-wrap/1` (10 §3.4), `data: {needs_you[], unshared[], claims[{claim_id, label, path, state, waiting}], unsaved{by_author[{name, self, n}], earlier, paths[]}, revert?[], draft{state: ok|empty|unavailable, headline, bullets[{zone, labels[], names[]}], dropped, to8}, commands[{kind: save|handoff|away|stop, cmd, blocked_code?, note_code?}]}`; `revert`, `handoff` and `away` exist only when F10/F08/F01 are merged. `draft` strings carry the paste-safe pass of §2.2. In slash mode arrays are cut and `data.truncated` is set (10 §3.4).

### 2.8 Authors of unsaved work (W5)

For each path of LIVE_UNSAVED (`paths(diff(tree(EPOCH_BASE), tree(LA_C)))`), the authors are the author names of the single-parent live commits in `(G_LA, LA_C]` whose `diff-tree --name-only` names it, where `G_LA` is the base-move commit that introduced `EPOCH_BASE = live_base(LA_C)`; base-move commits are skipped. A path changed by several people counts once under each of them. A path that no commit in that range names (it was changed after the last save's `Lk` but before the base move that followed, or, when the newest base move came from a human branch commit, it is older unsaved live work) is counted under `UI_WRAP_UNSAVED_EARLIER`, never dropped. Paths are listed in code-point order. The walk shares §2.2's memo, background priority and 10 s budget; over budget, W5 prints only the total `{n}` files with `UI_WRAP_UNSAVED_TOTAL` and no per-author lines.

## 3. How it uses existing mechanisms

- **Board/fold:** reads the folded `claims`, `requests`, `holds`, `peers` (02 §3.3) the daemon already holds; writes no op. LIVE_UNSAVED and `(G, L]` come from the live chain already on this PC (`refs/cowork-remote/*`); author per path for W5 uses `diff-tree --name-only` of each commit in `(G_LA, LA_C]` (§2.8), memoized and prioritized like §2.2.
- **Holds and CSs:** the open-CS table and journaled ready pairs (HLD-36, HLD-40), PIN records (glossary §9), reason keys (05 §2).
- **status.json:** headline only; no field added (UX-08). **IPC:** one new read-only request kind `wrap` in the IPC schema (09 §3.11), same handshake and capability limits (SEC-23); it returns codes and typed params, never rendered text.
- **Rendering:** `render()` and `sanitize()` (10 §3.2), the slash frame and cap (10 §3.3), UX-07's "no empty headers" and truncation line.
- **Save:** §3.7.2 is refactored into `saveAttribution`; save behaviour, trailers, human evidence (glossary §25 F5) and preview/confirm (LIF-02) are unchanged.
- **Not used:** OS notifications (wrap is pull-only, no `NT_` class), hook `systemMessage`, MCP tools (Claude's eight tools are unchanged; Claude sees wrap only when the human runs it, or by running `node …/cli.js wrap` through Bash, which 06 §3.9 row (d) lets pass like `status`), the viewer.

## 4. Privacy and safety

- Nothing leaves the PC: no network call, no board write, no log line beyond the CLI's usual code-only entry. The draft is **never written** to the board, `status.json`, logs, `tmp/` or any file (same rule as the 10 §3.8 three-way view); it exists only in the CLI output and in `--json` stdout.
- Shown data is what `status`, `queue`, `log` and the save preview already show (display names, labels, paths). Never shown: note text (only `UI_HAS_NOTE`), host text (`UI_HOST_SAID_WITHHELD` rules apply), `local_only` record content (path and line only), quarantined bytes, e-mails, `peer_id`s, the messaging token, wall-clock times.
- Board-derived strings are data: sanitized, capped, inside the slash frame, never in `{cmd}`. The draft, which the human is invited to paste into a shell-run slash command, also gets the paste-safe pass (§2.2), so copying it can never execute a teammate's display name or label.
- Nothing about teammates is ranked: W5 is ordered by name, never by file count, and no section compares people.
- No automatic save, ever: wrap holds no evidence and issues no acting IPC request; `save` keeps requiring human evidence (glossary §25 F5, SEC-25) and preview/confirm. Claude cannot turn a draft into a save.

## 5. Requirements

- **FEAT-F12-01** `/cowork wrap` MUST be a read-only verb (glossary §15): it MUST NOT change any ref, hold record, claim, config, working-tree file or `status.json`, MUST NOT fetch or push, MUST NOT require or consume human evidence and MUST NOT renew the human lease (INV-UX-READONLY).
- **FEAT-F12-02** It MUST print sections W1–W8 of §2.1 in that order with the stated sources and caps, MUST print no empty header, and W2 MUST contain every item UX-07 requires in `status` section 2.
- **FEAT-F12-03** In slash mode the output MUST be ≤ 4,000 chars, framed and ANSI-free; W1 and W8 MUST always be complete; truncation MUST follow §2.1's priority and print `UI_TRUNCATED_SLASH` directly above W8 (UX-03 as amended in §7). A typical wrap SHOULD be ≤ 2,500 chars.
- **FEAT-F12-04** On IPC failure it MUST print the headline, `UI_DETAIL_UNAVAILABLE` and the headline's next line, and exit 0.
- **FEAT-F12-05** `waiting(claim)` MUST be computed exactly as §2.5.
- **FEAT-F12-06** The latest edit-check result MUST live only in the one daemon-memory store `last_check` of §2.4 (F14 §4's; no second store), MUST reach the CLI only through the `wrap` IPC reply (and F14's `flow` reply when F14 is merged), MUST be rendered only through F14's `UI_FLOW_LAST_*` codes when F14 is merged and otherwise through the six `UI_WRAP_EDITCHECK_*` codes, MUST NOT render a `no_snapshot`/`merge_conflict`/`no_merge` failure as a check 1–4 failure, and MUST NOT reach `status.json`, the board, logs, any seat carrier, human mirror or OS notification.
- **FEAT-F12-07** Save trailers (§3.7.2) and every draft MUST come from the one function `saveAttribution(G, L, Hb)`; for equal inputs and equal mapper results the draft body (headline and bullets) MUST be byte-identical on every PC with the same `L_h`; the `UI_DRAFT_AS_OF` line is a per-PC label outside this rule. A per-commit result produced under a fired time budget MUST NOT be memoized.
- **FEAT-F12-08** The draft MUST follow §2.2's grammar, ordering, caps and bullet length rule, and MUST be labelled with `UI_DRAFT_LABEL` wherever it is shown.
- **FEAT-F12-09** Every draft placeholder MUST pass `sanitize()`, its type cap and the §2.2 paste-safe pass (no `"`, `` ` ``, `$`, `\`, `!` in any draft line, catalog text included); the headline and every bullet MUST pass `scanSecrets(commit_message)` or be replaced/dropped and counted; the draft MUST NOT contain a `Cowork-` line, e-mail, `peer_id`, note text, host text, file content or date.
- **FEAT-F12-10** No draft text and no teammate display name MAY appear inside a `{cmd}` placeholder; W8 lines MUST come from the fixed command table, with only validated ids (SEC-35) and literal placeholders inserted.
- **FEAT-F12-11** The draft MUST NOT be written to any ref, file, log or `status.json`.
- **FEAT-F12-12** The save preview MUST show the `(G, Lk]` draft per §2.6, MUST NOT include it in the preview id, and SHOULD warn with `UI_SAVE_SUMMARY_IS_DRAFT`; `SAVE_SUMMARY_EMPTY`'s condition MUST stay unchanged.
- **FEAT-F12-13** Lines and sections for F01, F08 and F10 MUST be omitted entirely when those features are not merged.
- **FEAT-F12-14** `--json` MUST emit `cowork-wrap/1` (§2.7), shipped as `dist/schema/cowork-wrap-1.json`.
- **FEAT-F12-15** F12 MUST NOT add a board op, trailer, `status.json` field, OS-notification class, Claude-facing template or viewer event. F25 `--save-notes` (when merged) MUST call `saveAttribution` and the §2.2 renderer, not a copy.
- **FEAT-F12-16** Draft and W5 attribution MUST run at background priority in the REG worker pool (§2.2): the lowest priority in the pool (below the edit check), one commit per job, at most one worker at a time, and no gate, CONFIRM, edit-check or T0 job MAY be queued behind a draft job.
- **FEAT-F12-17** W5 MUST list this peer first and then authors by display-name code point, MUST NOT order or rank by count, and MUST count every LIVE_UNSAVED path (unattributed paths under `UI_WRAP_UNSAVED_EARLIER`, §2.8).
- **FEAT-F12-18** W8 MUST print `UI_WRAP_SAVE_BLOCKED` with the decided save refusal code instead of the save line, `UI_WRAP_SAVE_APPROVE_FIRST` when the save check is unapproved, `UI_WRAP_STOP_WOULD_REFUSE` with the decided stop refusal code, and `UI_WRAP_STOP_OPTIONAL` before every stop line.

## 9. Open questions (default ships if unanswered)

1. A paste-ready one-line `/cowork save "<draft>"` would save typing but needs an exception to the 10 §3.2 `{cmd}` rule (the paste-safe pass of §2.2 already makes the text shell-safe, but a board-derived string inside a printed command line is still a prompt-injection surface in slash output). *Default:* no; the human copies from W7.
2. Should `status` also show the edit-check reason? *Default:* only through F14 (`status --flow`), which shares the one `last_check` store; without F14, `wrap` only. Either way nothing is pushed to any carrier (COO-10 as amended).
3. **Attribution range (08 §3.7.2, inherited).** `(G, Lk]` starts at the base-move commit that introduced `Hb`, but `diff(Hb, Lk)` also contains changes made after the previous save's `Lk` and before that save's base move (and, after a human branch commit, earlier unsaved live work). Their authors are walked by neither the save trailers nor the draft (W5 shows them as `UI_WRAP_UNSAVED_EARLIER`). Starting the walk at the `Cowork-Saved-Live` value of `Hb` when `Hb` is a save commit would close the gap for both. *Default:* F12 keeps 08's range unchanged ("save behaviour unchanged"); the fix is raised to the 08-lifecycle owner.
4. F01 (`away`) and F08 (handoff) have no proposal file yet; the `UI_WRAP_CMD_AWAY` / `UI_WRAP_CMD_HANDOFF` command forms are placeholders until they do. *Default:* both lines are omitted (FEAT-F12-13) until those features define their verbs.
5. **Multi-line paste into a slash command (unmeasured).** The draft is multi-line, and nothing in the spec measures whether Claude Code's `!` preprocessing passes a multi-line `$ARGUMENTS` through intact (10 §8 Q3 covers only `CLAUDECODE`). Inside double quotes a newline is literal for both shells, so the paste-safe set stays correct; if the host flattens or rejects multi-line arguments, only the first line (the headline) survives the slash path. *Default:* the guides document the terminal path (`node "<plugin root>/dist/cli.js" save "…"`) for multi-line summaries until the glossary §26.3 interactive runs measure it.

## Review notes

Adversarial review, 2026-10-08, against glossary rev 2.4, chapters 01–12, the Plan 2 contract and the sibling proposals F04, F10, F14. Verdict: **keep with changes**; not implementable now (needs Plans 3–7), with a corrected Plan 2 follow-up carve-out.

**Already in the spec?** No. Nothing in `docs/spec` defines an end-of-day screen, a `wrap` verb or a summary draft. Overlaps, all handled by reuse rather than duplication: `status` sections 1–2 and `queue` actions (W1, W2 reuse them verbatim), the save preview's "files with per-file contributors" (the draft adds a grouped, copyable summary of the same `(G, Lk]` data), and F14's in-flight view and `last_check` (now the one shared store, §2.4).

**Changed in this file**
1. **Paste hazard (security).** The design kept the draft out of `{cmd}`, but its own workflow has the human paste the draft into `/cowork save "…"`, whose `!` line passes `$ARGUMENTS` through a shell; `sanitize()` does not neutralise `"`, `` ` ``, `$`, `\`, so a teammate's display name `$(…)` would execute on paste. Added the §2.2 paste-safe pass (full-width replacement of `"` `` ` `` `$` `\` `!` in draft placeholders, catalog lint for `UI_DRAFT_*`), FEAT-F12-09, the SEC-34 edit and a paste test in T-F12-draft-hostile (POSIX shell and PowerShell).
2. **UX-03 contradiction.** UX-03 requires slash output to *end* with `UI_TRUNCATED_SLASH`; the design prints it above W8. Kept the design (commands are never cut) and added the UX-03 / 10 §3.3 amendment to §7.
3. **Second edit-check store and the silence rules.** F14 already defines `last_check` per open seat CS and amends COO-10, HLD-67, 06 §3.8.4 and glossary §27.1; F12 invented a parallel store and claimed 07 needs no change, although COO-10 forbids failing-edit-check text "on any carrier" and REG-36 / 04 §3.20 forbid "status text". §2.4 now uses the one `last_check` store (F12 introduces it with F14's shape if it lands first), renders F14's codes when F14 is merged, and §7 lists the shared amendments (marked "= F14") plus the 04 REG-36/§3.20 wording. `editCheck` reasons `no_snapshot`/`merge_conflict`/`no_merge` were mislabelled as check 1–4 failures; added `UI_WRAP_EDITCHECK_UNCHECKED`.
4. **Cross-PC determinism was overstated.** The REG mapper degrades per PC when a parse or mapper time budget fires (`NO_TABLE{budget}`, glossary §20), and lifetime memoization would freeze such a result. FEAT-F12-07 now requires equality only for equal mapper results, budget-degraded results are never memoized, the deterministic test uses small files, and a memo test was added.
5. **Worker-pool contention.** A 10 s attribution burst in the shared REG worker pool could delay gate/CONFIRM/edit-check jobs of live seats. Draft and W5 attribution now run at the lowest pool priority, one commit per job, one worker at a time (§2.2, FEAT-F12-16, T-F12-worker-priority).
6. **Preview id.** 08 §2.1 digests "exactly the oids, paths and record ids the preview printed", and the draft prints root-level file names; §7 now amends 08 §2.1 and LIF-02 so the draft is explicitly not a source of `items`.

Stop line: added `STOP_GIT_OP` and `STOP_HOLDS_NOT_DURABLE`, and `UI_WRAP_STOP_OPTIONAL`, because stop is not an end-of-day action (it releases every claim, parks held changes, stops coordinating other sessions and needs `/cowork start` again, while closing a session already releases its claims and the daemon idles out by itself). W8 reservation raised to 900 chars for that line. FEAT-F12-18, T-F12-commands.
