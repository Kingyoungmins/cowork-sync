# cowork-sync Implementation Roadmap

**Spec:** [`docs/spec/00-glossary.md`](../../spec/00-glossary.md) (rev 2.4, binding) and chapters 01–11. Entry point: [`docs/superpowers/specs/2026-10-01-cowork-sync-design.md`](../specs/2026-10-01-cowork-sync-design.md). Approved by the user on 2026-10-02.

The spec covers seven subsystems that build on each other. Each one gets its own implementation plan. A plan is written when the plans it depends on have landed, because its tasks name the real interfaces those plans produced. Every plan leaves `main` with working, tested software.

**Feature proposals (rev 2.5, 2026-10-08).** [Glossary §29](../../spec/00-glossary.md) adds eight nice-to-have features: F04 catch-up (`/cowork since`), F05 claims ahead, F10 revert own change-set (`/cowork revert`), F12 wrap and save draft (`/cowork wrap`), F14 in-flight view (`/cowork status --flow`), F29 highlight reel, F32 follow a teammate and F34 postcard. Their design files are `docs/proposals/F*.md`; [`docs/proposals/QUEUE.md`](../../proposals/QUEUE.md) orders the work, and a design file wins where the queue differs. None changes the protocol (`proto = 1`). Each plan row below names its share as "(rev 2.5, Fxx)", and each share lands with its tests. Text that depends on an owner decision names it (D1–D5, glossary §29.1). All five were proposed on 2026-10-08 and **decided by the owner the same day**: D1 shows the latest edit-check result in full in `status --flow` and `wrap`, as a slash command and in a terminal (never pushed); D2 with 05-holds §8 Q18 option (a) (the revert's shrink mark follows a clean teammate rebase); D3 F32 = Plan 8a Task 19; D4 the first public release happens only after Plan 8b (Plan 7 prepares, Plan 8b's last task publishes); D5 only F04-a starts early, right after Plan 2. The privacy scope of FEAT-F04-12 (F04 surfaces only) was decided too.

**Host-dependent work** (the inbox wire format in real sessions, daemon lifetime under real hosts, human-evidence timing, cross-network lease races, long-running credentials) is built in plans 5 and 6. It is not released until the three remaining human spikes of glossary §26.3 have run: a second PC on another network, a 24 h credential run with a forced sign-out, and interactive terminal and VS Code runs.

**Execution order:** 1 → 2 → 3 → 4 → 5 → 6 → 7. Plans 4 and 5 may overlap once plan 3 has landed, because they touch disjoint modules (`src/regions/**` and `src/claude/**`). Plan 8a starts when plan 2 has landed and runs alongside plans 3–7 in its own module `src/viz/**`, plus the `view` dispatch line of the `cli.js` entry, the additive board interfaces of 12-visualizer §9.7 and, when no earlier plan has created them, first versions of the shared `sanitize` and `render` modules with their spec signatures; Plan 8b follows plans 5 and 7 and ends with the first public release (D4). Each later plan adds the scene events of its ops to Plan 8's fixtures and golden timelines: once Plan 8a has landed, the exit criterion of each of plans 3–7 includes that the T-VIZ-timeline-fixtures rows of its plan (12-visualizer §3.4 Plan column) produce their scene events instead of `unknown`, that `startScene` reads the fold-state fields the plan fills (12 §3.3.5), that T-VIZ-golden-sim passes after a reviewed `--update`, and that the bundled demo shows the plan's facts.
