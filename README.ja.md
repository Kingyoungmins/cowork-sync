# cowork-sync

ウェブサイト（英語）: [kingyoungmins.github.io/cowork-sync](https://kingyoungmins.github.io/cowork-sync/)

cowork-sync は、1 つの git ブランチの作業ツリーを、複数のクローン間でリアルタイムに同期する Claude Code プラグインです。チームメンバーはそれぞれ自分の PC で、自分のクローンを使い、自分の Claude Code セッションで作業します。誰かがファイルを保存すると、その変更が全員の作業ツリーに届きます。通信経路はプロジェクト自身の git リモートだけで、サーバーはありません。

cowork-sync は個人のソース公開型（source-available）プロジェクトです。いかなる会社や雇用主とも提携しておらず、後援や推奨も受けていません。ライセンスは FSL-1.1-ALv2 です（[LICENSE.md](LICENSE.md) を参照）。コントリビューションには、[CONTRIBUTING.md](CONTRIBUTING.md) に記載された CLA が必要です。

## ステータス: v0.1.0-preview

これは初期プレビューであり、完成した製品ではありません。現在動くのは同期エンジンです。クローンごとに 1 つのバックグラウンドプロセス（デーモン）が、保存された編集を拾ってリモートに公開し、チームメンバーの編集をあなたの作業ツリーに書き込みます。実際の GitHub リポジトリと 2 つのクローンでテストしました。別々のファイルへの編集、同じファイルの 10 行離れた箇所への編集、同じ行への編集のいずれも、両方のクローンで同じ状態になり、履歴は 1 本のファストフォワードになりました。チームの活動をブラウザに描画する読み取り専用ビューアのコア部分も含まれています。まだ含まれていないものは次のとおりです。競合の保留（hold）UX（退避されたバージョンは保持されますが、それを見たり復元したりするコマンドはありません）、関数単位のクレーム、Claude Code セッションのフックと Claude 同士の連携（このプレビューでは Claude は同期を認識せず、その編集は他の保存ファイルと同じように同期されます）、完全なコマンドライン（save、doctor、プライベートリモートの確認などの開始時チェック、一時停止と再開）、そしてビューア 2（6 言語対応、録画、ハイライト集）。プレビュー版はテスト用リポジトリでのみ使ってください。完了した作業と今後の予定は [docs/STATUS.md](docs/STATUS.md) にまとめてあります。

## 必要条件

- Claude Code 2.1.270 以降。
- `PATH` 上の Node.js 20 以降（ソースからビルドする場合は 20.6 以降）。
- git 2.43 以降。start は、これより古い git を拒否します。
- Windows、macOS、または Linux。
- カスタム ref（`refs/cowork/*`）を受け付け、`--force-with-lease` を強制できる**プライベート**な git リモート。GitHub はどちらも満たします。start はホストを調べ、満たさないものは拒否します。
- git の credential helper から得られる認証情報。cowork-sync は git の入力プロンプトを無効にするため、認証情報がない場合は、ハングせずにはっきりした拒否メッセージが出ます。

## インストール

参加するすべての PC で、プラグインをインストールし、リポジトリの自分用クローンを持ってください。

Claude Code のセッションで:

```text
/plugin marketplace add Kingyoungmins/cowork-sync
/plugin install cowork-sync@cowork-sync
```

またはシェルから:

```sh
claude plugin marketplace add Kingyoungmins/cowork-sync
claude plugin install cowork-sync@cowork-sync
```

`/reload-plugins` を実行する（または Claude Code を再起動する）と読み込まれます。このマーケットプレイスでは、更新は自動で行われません。更新するには `/plugin marketplace update cowork-sync` を実行し、続けて `claude plugin update cowork-sync@cowork-sync` を実行します。プラグインを削除するには `claude plugin uninstall cowork-sync@cowork-sync` を実行します。

## 使い方

自分のクローンで Claude Code を開き、下のコマンドを入力します。Claude Code では、このプラグインのコマンド名は `/cowork-sync:cowork` になります。この名前を省略せずに入力してください。同じ動詞（verb）はターミナルからも `node "<plugin folder>/dist/cli.js" <verb>` として実行できます。そのパスは `/cowork-sync:cowork view` で表示されます。

| コマンド | 内容 |
| :- | :- |
| `/cowork-sync:cowork start [--branch <b>]` | このリポジトリの現在のブランチで同期を開始します。最初の PC がリモートに共有ボードを作成し、以降の PC はそれに参加します。デーモンはバックグラウンドで動き続けます。 |
| `/cowork-sync:cowork status` | 短い概要を表示します。状態（`ok`、`degraded`、`offline`、`frozen`、`down` など）、ブランチ、公開または適用待ちの内容です。 |
| `/cowork-sync:cowork view` | 読み取り専用ビューアを開くコマンドを表示します。ビューアはターミナルからのみ開けます。表示されたコマンドをターミナルで実行すると、ブラウザで開きます。お使いのビルドにまだビューアのプロセスがない場合は、`RF_VIZ_START_FAILED` で拒否されます（[CHANGELOG.md](CHANGELOG.md) を参照）。 |
| `/cowork-sync:cowork stop` | デーモンを正常に停止します。ファイルはそのまま残ります。 |
| `/cowork-sync:cowork help` | コマンドの一覧を表示します。 |

コマンドが拒否されると、コード付きの理由と、実行すべきコマンドを示す `next:` 行が表示されます。デーモン自体が起動を拒否した場合は、`the daemon did not start; it said:` の後にデーモン自身の出力行が続きます。

`start` が確認すること:

- メインのクローンで実行されていること。リンクされたワークツリー（linked worktree）とサブモジュールは拒否されます。
- ブランチがチェックアウトされ、リモートに存在し、リモートより進んでも遅れてもいないこと。先に push または pull してください。マージやリベースが進行中であってはいけません。
- リモートの fetch URL と push URL が同じで、`insteadOf` による書き換えが適用されていないこと。
- クローンごとにデーモンが 1 つだけ動いていること。
- 最初の start 時にコミットされていない変更がある場合は、停止して選択を求めます。チームと共有するか、この PC だけに残すかです。

同期中は次のようにします。

- いつもどおりファイルを保存してください。保存した編集は公開され、チームメンバーの編集はあなたのファイルに書き込まれます。
- 同期中のクローンで、`HEAD` を動かす git コマンド（commit、switch、checkout、pull、merge、rebase、stash）を実行しないでください。`HEAD` が元の位置に戻るまで、同期は凍結（freeze）します。先に同期を停止してください。
- 共有された作業をブランチ上のコミットにする `save` ステップは、まだありません。それは完全なコマンドラインで提供されます。このプレビューは、テスト用ブランチでライブ同期を試すためのものとして扱ってください。

各クローンは、自分のファイルを `.git/cowork/` の下に保持します。`status.json`（現在の状態）と `log/daemon-0.jsonl`（デーモンのログ）です。

## 仕組み

1. 各クローンが 1 つのデーモンを動かします。デーモンは専用のプライベートな git インデックスを通じて保存済みファイルを読み、あなたのインデックスには一切触れません。
2. 共有状態は、リモート上の 2 つのカスタム ref にあります。`refs/cowork/<branch>/board` は、ファストフォワードのみのボードコミットの連鎖で、これが正（authority）です。`refs/cowork/<branch>/code` は、最新の共有ツリーのミラーです。これらの ref では、ブランチ名はパーセントエンコードされます。
3. すべての push は、リース（`--force-with-lease`）で守られたファストフォワードです。そのため、どの PC も他の PC の更新を上書きできません。負けた側は fetch してやり直します。チーム全体の予算（1 分あたり 12 回の push。スロットリングを受けた後の 30 分間は 6 回）により、ホストへの負荷を低く保ちます。
4. 受信した変更は、明示的なマージベースを指定して `git merge-tree` でマージされます。
5. ファイルは、デーモンが最後に読んだバイト列のままである場合にだけ書き込まれます。そのため、保存したばかりの編集が上書きされることはありません。ファイル群の書き込みは、すべて行われるか、まったく行われないかのどちらかです。
6. 2 人が同じ行を変更した場合、一方のバージョンが採用され、もう一方は保留記録（hold record）としてあなたのクローンに保持されます。捨てられることはありません。
7. 設定、フック、CI のファイル（`.claude/`、`.github/workflows/`、`.gitattributes` など）は、ライブ同期されません。ボードの履歴が書き換えられた場合は、復旧されるまですべての PC が凍結します。
8. プレビュー版は、あなたのブランチ（`refs/heads/<branch>`）に push することはありません。通常の `git fetch` ではカスタム ref はダウンロードされないため、普段の git 履歴は汚れません。

## 安全上の注意

- cowork-sync はあなたの作業ツリーに書き込みます。チームメンバーの編集も同様です。まずテスト用リポジトリで試し、大切なものはバックアップしてください。
- **プライベート**なリモートだけを使ってください。同期中のクローンで保存したものはすべて `refs/cowork/*` に push され、リポジトリを読める人なら誰でも取得できます。プレビュー版は、リモートがプライベートかどうかをまだ確認しません。
- 名前が秘密情報のように見える新規ファイル（`.env`、`*.pem`、`*.key`、`id_rsa*`、`*credentials*` など）は共有されません。ファイルの中身に秘密情報が含まれていないかは、まだスキャンされないため、同期するファイルに秘密情報を入れないでください。
- 新規の 1 MiB を超えるファイルは共有されず、50 MiB 以上のファイルはライブ同期されません。
- 同期を停止したりプラグインをアンインストールしたりしても、カスタム ref はリモートに残ります。すべての PC が停止した後であれば、手動で削除できます。例: `git push origin --delete refs/cowork/main/board refs/cowork/main/code`。
